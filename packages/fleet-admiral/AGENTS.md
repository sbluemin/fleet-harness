# fleet-admiral

Fleet's Admiral policy layer for prompts, protocols, tools, Agent CLI activation, and Fleet runtime assembly.

## Directory index

| Directory | Responsibility |
|---|---|
| `src/protocols/` | Prompt gate and always-on standing orders |
| `src/agent-cli/` | Provider activation, launch specification, and Fleet rendering |
| `src/agent-runtime/` | Fleet MCP and executor runtime assembly |
| `assets/skills/` | Authoring source for built-in Fleet skills |
| `tests/` | Prompt, asset, launch, and runtime contracts |

## Constraints

- This package owns Fleet policy and launch/runtime specifications, not host UI, PTY, process spawning, browser lifecycle, or host-owned application state.
- Host integrations and optional domain tools enter through explicit dependencies; this package must not import runtime hosts.
- Only unconditionally read-only Wiki tools (`wiki_briefing` / `wiki_orient` / `wiki_read` / `wiki_resolve`) are globally shared with Carriers. Every other Wiki tool — mutation, staging, lint, schema, and patch approval / rejection — is host-only; no Carrier receives Wiki mutation tools, and the host performs Fleet Wiki operations directly.
- Gateway doctrine host sessions never receive the `carrier_dispatch` / `carrier_jobs` tools; the exclusion is enforced at session-token issuance, not only in the prompt.
- Public exports are a deliberate root whitelist. Do not add wildcard exports, compatibility subpaths, or source deep-import contracts.
- `assets/skills/` is the authoring source of truth; `src/agent-cli/assets.generated.ts` is generated by `scripts/generate-fleet-admiral-assets.mjs` and must not be hand-edited.
