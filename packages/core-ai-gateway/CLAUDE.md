# core-ai-gateway

Translates Anthropic Messages traffic onto non-Anthropic provider backends.

## Layer index

| Layer | Responsibility |
|---|---|
| `src/canonical/index.ts` | Provider-neutral request/event vocabulary every adapter speaks |
| `src/anthropic/` | Client-facing Anthropic protocol seam: `protocol.ts`/`passthrough.ts` are cross-provider shared client-facing protocol normalization, `native.ts` is Anthropic-owned endpoint/header/auth forwarding policy, `gateway.ts`/`claude-context.ts` are the client-facing gateway/Claude compatibility seam (not a provider-shared allowlist) |
| `src/transport/` | Provider-unaware transport mechanics: SSE framing, token estimate, wire log, keepalive, credential file I/O |
| `src/gateway-router/` | Sanctioned cross-provider HTTP dispatch surface: the Anthropic-compatible /v1 serving seam behind explicit host-injected dependencies. `router.ts` routes; `router-policy.ts` carries the request-shaping contract and its step implementations |
| `src/<provider>/` | One folder per provider (`codex/`, `cursor/`, `kimi/`, `opencode-go/`), each declaring its own `router-policy.ts`. OpenCode behavior is additionally split by wire under `src/opencode-go/{anthropic,responses,chat-completions}/` |
| `src/models.ts`, `models.json`, `benchmarks.json` | Model catalog, context windows, effort ladders, and third-party benchmark evidence |
| `src/settings/` | Which catalog models a user exposed and where that choice is stored: stored shape, catalog-checked validation, selection resolution, the opt-in `providerPriority` spend order, and the `<dataDir>/ai-gateway.json` durable store |
| src/quota/ | Provider-neutral quota vocabulary, window normalization, and the cached usage service; per-provider probes live beside each provider as src/<provider>/quota.ts |

## Routing doctrine

- `models.json` + `benchmarks.json` + `src/models.ts` are the single central catalog SSoT; never split them or move ownership. The catalog carries each vendor lineup's current generation only — a superseded generation leaves the catalog instead of aging in place.
- `capabilityClass` records the provider's own lineup positioning (`flagship`/`standard`/`light`) — the quality prior where no measured evidence exists: what the provider claims, never a measurement. Classify a new model in this order: a `providerModelId`-linked service-tier sibling inherits its base's class; otherwise the provider's naming grammar decides — top tier tokens (`max`, `pro`) and the current generation of an unsuffixed mainline are `flagship`, mid tokens (`plus`) and superseded generations of a former flagship are `standard`, light tokens (`flash`, mini-class names like `luna`, and an unlinked `-fast`) are `light`. Resolve ambiguity downward (overclassing seats a light model in judgment work; underclassing merely costs one candidate) and leave routing aliases (`auto`) unclassed — validation enforces both.
- `benchmarks.json` records third-party measured quality evidence from a single source — CursorBench — joined to catalog entries only through an explicit `benchmarkKey`, never by id-string matching. The single source is deliberate policy: benchmark figures are harness-relative and never compare across sources, so a second source only blurs host judgment with incomparable numbers. A model CursorBench has not measured carries no benchmark entry at all — the `capabilityClass` prior alone guides host judgment there — and reintroducing a second source is a user-authorization decision, not an authoring one. Where figures exist they outrank the `capabilityClass` claim. Validation enforces the join invariants; authoring and figure-update rules live with the schema in `src/models.ts`.
- Provider behavior belongs to `src/<provider>/`, and OpenCode's wire-specific behavior additionally to its wire subfolder.
- `src/gateway-router/` is the sanctioned cross-provider HTTP serving seam: it may import provider folders for dispatch, receives every host concern (settings reader, credentials, originator, model override, diagnostics sink, fetch) as explicit dependencies, and carries no host identity, no environment lookups, and no host lifecycle of its own.
- Which shaping a caller request receives before it reaches a provider is that provider's declaration, never the router's branch. `router.ts` routes — body, model, exposure, credential, gateway construction, dispatch, error mapping — and holds no per-provider request condition. `src/gateway-router/router-policy.ts` owns the `GatewayRequestPolicy` contract and every step's implementation; each `src/<provider>/router-policy.ts` states which steps its wire deserves and why. A provider without a policy fails to compile rather than inheriting another provider's answer, and the provider-boundaries test pins both that file's presence and its shape.
- The step implementations stay with the seam because they read Claude Code's own request vocabulary from `src/anthropic/claude-context.ts`, which no provider folder may import. So the one dependency pointing back at the seam is a provider naming the contract it implements, and it is `import type` only — the edge is erased at runtime and the seam still owns every real module. Any other provider import of `src/gateway-router/` is a violation.
- Withholding a client tool and forwarding the client instruction that steers toward its alternative are **one decision per provider**. Withhold the tool while dropping the instruction and the model is left with no route it was told about; forward the instruction while advertising the tool and the model receives a catalog it is instructed to ignore. Whichever half a policy moves, it moves the other with it, and the policy matrix test pins both columns together.
- Same wire protocol is not a reason to share provider request/response/tool/header/capability semantics — duplicate provider semantics deliberately.
- Only canonical protocol vocabulary (`src/canonical/`), provider-unaware transport mechanics (`src/transport/`), and exactly two Anthropic normalization modules — `src/anthropic/protocol.ts` and `src/anthropic/passthrough.ts` — may be shared across providers. `src/transport/` must not import any provider folder, and `src/anthropic/native.ts` is Anthropic-owned provider semantics other providers must not import.
- Provider request/response/tool/header/capability exceptions cannot live in `canonical/`, `transport/`, or the root facade.
- `src/settings/` is a catalog reader, never a provider: it may consume `src/models.ts` and the Claude compatibility seam, but must not import a provider folder or carry provider request/response semantics. Hosts wire it with an explicit data root and an optional legacy directory; the package resolves no host path of its own.
- `src/index.ts` is a compatibility facade only: it re-exports the public surface from the new locations and must not add provider branching or behavior.
- The one sanctioned seam→provider coupling is `AnthropicMessagesGateway`'s backwards-compatible default constructor (`src/anthropic/gateway.ts` → `codex/responses/adapter.ts`, the legacy `OpenAIResponsesAdapter`). It is pinned by the provider-boundaries test; any other anthropic-seam import of a provider folder is a violation.

## Constraints

- Keep Fleet orchestration and persona semantics out of this package; it knows providers, not Fleet personas.
- Provider usage/quota probing lives beside each provider (src/<provider>/quota.ts) with shared window vocabulary and caching in src/quota/; collectors receive their credential and auth dependencies explicitly — no default auth construction inside this package.
- Each provider Responses implementation that applies strict mode rewrites every compatible tool schema into strict mode and strips the resulting nulls back out on the way in. **These two are one mechanism per implementation.** Change either alone and arguments silently gain or lose meaning: a surviving null reads as a real value to the client, and an un-rewritten schema loses the omission guarantee. The rewrite, the null stripping, and the argument-delta dropping below stay local to each such implementation — never centralize or import this semantic logic across providers.
- Strict compatibility is decided by an allowlist of JSON Schema keywords, never a denylist. The costs are asymmetric — judging a tool incompatible costs that one tool its guarantee, while wrongly admitting one returns a 400 that fails the entire request, every other tool included. Widen the allowlist only against an observed acceptance.
- Each provider Responses implementation that applies strict mode drops `response.function_call_arguments.delta` deliberately. Nulls cannot be stripped from a partial JSON fragment, so forwarding fragments would let the client reassemble un-stripped arguments. Restoring argument streaming reintroduces the defect.
- Strict mode makes omission expressible; it does not stop a model from filling an argument. Models still send the default quoted in a property's own description, and stating the omission rule in that description was measured to change nothing. Do not re-attempt schema-side persuasion — treat leftover default-valued arguments as accepted, since suppressing them cannot be distinguished from a caller who meant the default.
- The Cursor path has no equivalent guarantee. Its optional-argument pollution is known and unaddressed; do not assume parity between adapters.
- Cursor's redirect targets and its withheld catalog entries are two predicates, deliberately not one. A native exec may be translated into any redirect target, while only a tool whose capability Cursor owns outright — its shell — is kept out of the advertised catalog, because advertising both spellings of one capability invites the model to pick at random. `Grep` is a redirect target that is **not** withheld: the translation carries only the subset of that schema the native shape can express and fail-closes on the rest, so the caller's own tool is the better route and the redirect remains the fallback for a native call the model makes anyway. Collapsing the two back into one predicate either kills a redirect or hides a tool that had no duplicate.
- The Cursor Run gates on its HTTP response status before any body byte is read as Connect framing, and fails a transport end that decoded no frame. **These two are one guarantee.** A rejected Run's body is not Connect framing, so decoding it produces neither a frame nor an error; drop either half and an upstream rejection completes as a successful, empty assistant turn instead.
- Every Cursor model runs client tool calls over the live Run bridge — Auto, Composer, and Grok included. Measured: each of them suspends our client tools and continues from their results exactly as the named models do, and the exclusion they used to carry was hiding a correlation defect, not a provider difference. Re-excluding a model puts a cold dial and a full conversation re-upload on every one of its tool calls, so it takes a measurement, never a precaution.
- Cursor keeps writing a turn after the gateway has sealed it, and the park gate plus the three shapes that arrive late — the sealed turn's own tail, the echo of a call the client already answered, and a call the model raced past the seal — are **one mechanism**. The tail and the echo are tolerated where they are recognized, the raced call is deferred and replayed into the next segment, and everything else still discards the Run. Tighten one alone and a warm bridge dies one frame after every park; loosen one alone and the client is handed a call it never ran, or a turn never ends because an unsuspended item holds the finish gate open forever. Which frame belongs to which shape lives with the classifiers in `src/cursor/native/adapter.ts`.
- The OpenCode Chat Completions implementation gets its schema guarantee inbound, never outbound: that wire accepts `strict: true` and ignores it, so it prunes undeclared keys from completed tool-call arguments and rewrites no schema. Do not re-attempt an outbound rewrite there. Like the image-input policy the pruning binds to the provider instance and must never widen the public generic Chat Completions class, and it drops only *undeclared* keys — suppressing a declared argument stays forbidden by the strict-mode rule above. Which schemas it will and will not prune, and the measurement behind the rule, belong with the walker in `src/opencode-go/chat-completions/adapter.ts`.
- `FLEET_GATEWAY_WIRE_LOG` names the default file target for the inbound tool catalog, the canonical and provider wire bodies, and every response event as unlimited-append JSONL. An explicit in-process override takes precedence over the environment target; only override targets with `maxBytes` rotate at that limit and retain one `.1` backup. This log is the only way to see the argument JSON a model actually produced — provider behaviour differences are not otherwise observable from either side of this package.
