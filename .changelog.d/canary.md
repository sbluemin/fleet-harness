### fleet-cli
#### Fixed
- A session launched on an OpenCode Go model through the AI Gateway no longer fails a tool call when the model invents an argument the tool never declared. Keys the tool's own schema does not list are dropped from the arguments that backend returns, because it accepts `strict: true` and then ignores it.
  ko: AI Gateway를 통해 OpenCode Go 모델로 실행한 세션에서, 모델이 도구가 선언하지 않은 인자를 지어내도 도구 호출이 실패하지 않습니다. 이 백엔드는 `strict: true`를 받아들이고도 무시하므로, 반환된 인자에서 도구 스키마에 없는 키를 제거합니다.
- A session launched on a Cursor model through the AI Gateway no longer hangs for three minutes after a tool call, and stops re-sending the whole conversation on the turn that follows one. Cursor numbers a connection's tool requests from zero and omits that number when it is zero, keeps writing a turn's own tail after the gateway has already handed the tool call to the session, and echoes that call back once the session answers it. So the gateway could not match an answer to a connection's very first tool call and closed the connection instead of holding it open; when it did hold one open, it read the tail as the model running ahead and dropped it, and read the echo as a fresh tool call it was still waiting on, so that turn never ended and the session sat idle until its stall timeout. The gateway now reads an absent request number as zero, and treats the tail and the echo as the remainder of work it already handled. A model that starts one more tool call a moment after the gateway sealed the batch also no longer costs the connection: that call is held and handed to the session on the next turn instead.
  ko: AI Gateway를 통해 Cursor 모델로 실행한 세션이 도구 호출 뒤 3분씩 멈추지 않고, 그 다음 턴에서 대화 전체를 다시 보내지 않습니다. Cursor는 한 연결의 도구 요청 번호를 0부터 매기면서 그 번호가 0이면 아예 생략하고, 게이트웨이가 도구 호출을 세션에 넘긴 뒤에도 그 턴의 잔여 프레임을 계속 보내며, 세션이 답하면 그 호출을 그대로 되울려 보냅니다. 그래서 게이트웨이는 연결의 첫 도구 호출에 대한 응답을 짝지을 수 없어 연결을 열어 두지 못하고 닫았고, 열어 둔 경우에도 잔여 프레임을 모델이 앞서 나간 것으로 읽어 연결을 버렸으며, 되울린 호출은 아직 기다리는 중인 새 도구 호출로 읽어 그 턴이 끝나지 않은 채 세션이 정지 타임아웃까지 멈춰 있었습니다. 이제 요청 번호가 없으면 0으로 읽고, 잔여 프레임과 되울린 호출은 이미 처리한 작업의 나머지로 다룹니다. 게이트웨이가 배치를 봉인한 직후 모델이 도구를 하나 더 호출하는 경우도 더는 연결을 잃지 않습니다 — 그 호출은 보관했다가 다음 턴에 세션으로 전달합니다.
- A session launched on a Cursor model through the AI Gateway no longer stalls or announces that it is blocked when the model reaches for a Cursor built-in tool whose replacement is not advertised yet. Such a call is refused with instructions to use the session's own tool instead, but when the catalog did not yet list one the refusal named nothing, and the model concluded none existed, so it either stopped and told the user access was blocked, or called the Cursor tool again and was refused again. The refusal now points at the tool search that loads the deferred replacement, and where nothing can replace the call it says so and rules out retrying the Cursor tool.
  ko: AI Gateway를 통해 Cursor 모델로 실행한 세션이, 아직 광고되지 않은 대체 도구가 필요한 Cursor 내장 도구를 모델이 고를 때 멈추거나 차단됐다고 알리지 않습니다. 그런 호출은 세션 도구를 쓰라는 안내와 함께 거부되는데, 카탈로그에 아직 그 도구가 없으면 거부 메시지가 이름을 하나도 대지 못했고 모델은 대체 도구가 없다고 판단했습니다. 그래서 작업을 멈추고 사용자에게 접근이 차단됐다고 말하거나, Cursor 도구를 다시 불러 또 거부당했습니다. 이제 거부 메시지가 지연된 대체 도구를 불러오는 도구 검색을 가리키고, 대체할 것이 아예 없으면 그 사실을 밝히면서 Cursor 도구 재시도를 금지합니다.

#### Changed
- Cursor Auto, Composer, and Grok sessions now keep one connection across a tool call like every other Cursor model, instead of reconnecting and re-sending the whole conversation each time. They were held back on the reconnecting path on the assumption that Cursor ran their tools itself; measurement showed they hand their tool calls to the session exactly as the other models do, and what the assumption was really hiding was the request-numbering defect above.
  ko: Cursor Auto·Composer·Grok 세션이 다른 Cursor 모델과 마찬가지로 도구 호출 사이에 연결 하나를 유지합니다. 매번 다시 연결해 대화 전체를 올려보내지 않습니다. 이 모델들은 Cursor가 도구를 직접 실행한다는 전제로 재연결 경로에 묶여 있었는데, 실측 결과 다른 모델과 똑같이 도구 호출을 세션에 넘겼고 그 전제가 실제로 가리고 있던 것은 위의 요청 번호 결함이었습니다.
- A session launched on a Cursor model through the AI Gateway now carries its tool instructions as an always-applied Cursor rule, alongside the copy at the head of the conversation. The rule travels with each turn, including the turn that follows a tool result, so the instructions reach the model at the point it chooses a tool rather than only once at the start.
  ko: AI Gateway를 통해 Cursor 모델로 실행한 세션이 도구 지침을 대화 맨 앞의 사본과 함께 Cursor의 상시 적용 규칙으로도 전달합니다. 이 규칙은 도구 결과 다음 턴을 포함해 매 턴 함께 전달되므로, 지침이 시작 지점에서 한 번만이 아니라 모델이 실제로 도구를 고르는 지점에 닿습니다.
