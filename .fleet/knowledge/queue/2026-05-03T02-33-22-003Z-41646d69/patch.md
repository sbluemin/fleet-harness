{"id":"admiral-agent-architecture-philosophy","title":"Admiral Agent Architecture — Four Core Principles","body":"# Admiral Agent Architecture — Four Core Principles\n\nThe Fleet codebase enforces four architectural principles that take precedence over local convenience or micro-optimizations. Every contribution and review must align with these.\n\n## 1. Domain Boundary as Law\n\nThe split between `fleet-core` (Pi-agnostic Fleet domain) and `pi-fleet-extension` (Pi host adapter) is enforced by build/grep gates, not just convention.\n\n- `fleet-core` MUST NOT import `@mariozechner/pi-*` or `@anthropic-ai/*`. The single Pi-AI gateway lives in `pi-fleet-extension/src/agent/provider.ts`.\n- `pi-fleet-extension` consumes `fleet-core` only through the public root barrel (`@sbluemin/fleet-core`) or documented public subpaths. Deep imports into `src/**` are forbidden.\n- Pi UI, host event hooks (`pi.on/registerTool/registerProvider/...`), and `ExtensionContext`/`ExtensionAPI` belong exclusively to the Pi side.\n- When splitting a mixed module, the pure/domain half moves into `fleet-core`; only the Pi adapter half stays in `pi-fleet-extension`.\n\n## 2. Two Execution Patterns, Strictly Separated\n\nThe Admiral agent domain exposes two distinct execution patterns that must never be merged.\n\n| Pattern | Surface | Lifetime | Use Case |\n|---------|---------|----------|----------|\n| **Streaming** | `admiral.session.{ensure, sendMessage, deliverToolResults}` + `admiral.events` (module emit/register channel) | Long-lived ACP session, multiplexed per `sessionId` | Pi `streamAcp` host adapter; host `Map<sessionId, push>` routing |\n| **Closed-loop callback** | `admiral.executor.{executeWithPool, executeOneShot}` with `CarrierExecuteOptions.onMessageChunk/onThoughtChunk/onToolCall/...` | Single carrier turn, returns `CarrierExecResult` synchronously | `carriers_sortie` / `carrier_squadron` / `carrier_taskforce` tool execution |\n\n**Why the separation matters**: streaming routes events through a global module channel keyed by `sessionId`. Executor callbacks are owner-specific and finite. Forcing one pattern through the other path causes either listener leaks (callback as event) or routing collisions (event as callback).\n\nThe two patterns share `admiral/agent/internal/executor-engine.ts` pool wiring and `internal/post-connect.ts` setup helpers, but their public surfaces never overlap.\n\n## 3. Single Source of Truth (SSoT)\n\nSeveral invariants are guarded by a single owner. Duplication or shadowing is treated as a regression.\n\n| Concept | Owner | Rationale |\n|---------|-------|-----------|\n| Session persistence (`<piSessionId>.json` carrier→ACP map) | `admiral/agent/internal/session-runtime.ts` | Resume semantics depend on a single in-memory cache backed by one file |\n| Track status enum | `admiral/_shared/carrier-job-events.ts:TrackStatus` (queued / conn / stream / done / err / aborted) | Six values cover both panel UI and executor lifecycle; legacy `AgentStatus`/`ColStatus` removed |\n| MCP server URL + token routing | `admiral/_shared/mcp.ts` lazy singleton | One HTTP server, per-session Bearer tokens, FIFO routing isolated by token |\n| CLI provider catalog | `@sbluemin/unified-agent`'s `CLI_BACKENDS` | All `TASKFORCE_CLI_TYPES`, display names, colors, reasoning capabilities derive from this |\n| Fleet tool catalog | `admiral.agent.tools.list()` (default specs auto-registered, host extras via `registerExtraTools`) | Host queries metadata + invokes — never re-implements specs |\n\n## 4. Public Surface Discipline (Decision 28)\n\nThe only consumer-facing entry point is the package root barrel of `@sbluemin/fleet-core`. There is no `./admiral/agent` subpath.\n\nConsumers reach the agent domain through root barrel re-exports:\n\n- `executeWithPool`, `executeOneShot` (carrier execution)\n- `bindHostSession`, `shutdownAllSessions` (host lifecycle)\n- `disconnect`, `disconnectAll`, `cleanIdle`, `getSessionIdFor` (connections)\n\nInternal helpers under `admiral/agent/internal/` are never re-exported.\n\n## Forbidden Patterns\n\nThese patterns are prohibited package-wide and grep-gated:\n\n- `globalThis.<anything>` for shared state — module-level singletons only. Legacy keys `__pi_unified_agent_client_pool__` and `__pi_unified_agent_launch_config__` were removed.\n- Push-style \"ports\" parameters (`AgentToolPorts`) threaded into tool execution. Tools depend on `fleet-core` services directly.\n- `on*` callback parameters threaded through `fleet-core` public APIs. Events flow through `admiral.events` module-level register/emit only.\n- Builder functions injected by hosts (e.g., legacy `setCliRuntimeContext`). Prompt assembly (`buildInitialPrompt`, `buildRuntimeContextPrompt`) is fleet-core's responsibility; host adapters pass raw `userRequest` + optional `history` to `admiral.session.sendMessage`.","tags":["architecture","admiral","agent","fleet-core","philosophy","doctrine"],"created":"2026-05-03T02:33:22.003Z","updated":"2026-05-03T02:33:22.003Z","version":1,"rawSourceRef":"raw/2026-05-03-admiral-agent-architecture-philosophy-source.md"}
