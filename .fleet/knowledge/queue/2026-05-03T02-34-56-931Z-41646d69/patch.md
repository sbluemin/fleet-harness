{"id":"admiral-agent-migration-regression-fixes","title":"Admiral Agent Migration Regressions — 8 Fix Patterns to Prevent Recurrence","body":"# Admiral Agent Migration Regressions — 8 Fix Patterns to Prevent Recurrence\n\nThe admiral.agent migration (commit 8e9bb327) and the legacy `_shared/agent-runtime.ts` removal (commit 83ebdd0a) surfaced eight regression classes when consolidating provider-internal logic into the new domain. Each represents a structural risk that can recur in future agent-runtime refactors.\n\n## 1. Plain-flag Setter Loss in Round-trip Code Paths\n\n**Symptom**: tool result delivery throws \"이전 toolUse 이후 세션이 유효하지 않습니다\".\n\n**Root cause**: `session.activePrompt.mcpToolUseStarted = true` was missing from three locations where MCP tool calls are emitted (sendMessage path + two deliverToolResults paths). The flag is read by `deliverToolResults` to validate that a round-trip is in progress.\n\n**Lesson**: when migrating session state machines, audit every place that previously set `activePrompt.*` flags. Boolean flags are easy to forget because they have no return value.\n\n## 2. Stream Lifecycle Event Missing\n\n**Symptom**: streaming buffers entire response until done — chunks not delivered live.\n\n**Root cause**: `BlockTracker.ensureStarted()` was never called, so `stream.push({ type: \"start\", partial: output })` never fired. PI agent-loop waits for `start` before flushing chunks to the UI.\n\n**Lesson**: the Pi `AssistantMessageEventStream` requires a strict ordering (`start` → `text_start`/`text_delta`/`text_end` → `done`). Adapter rewrites must preserve every step of that envelope, not only the body events.\n\n## 3. Tool Hash Drift from Out-of-order Registration\n\n**Symptom**: every second user turn opens a fresh ACP session, losing context.\n\n**Root cause**: `registerExtraTools(scopeKey, ...)` was called *after* `ensure({...})`. On the first turn `ensure` computed `toolHash` from default tools only; on the second turn host extras were already registered, producing a different hash, which `ensureSession` interpreted as `tool 목록 변경` drift and replaced the session.\n\n**Lesson**: any state that participates in `ensure`-time hashing (tools, system prompt, model) must be registered **before** `ensure`. Order matters more than the API contract suggests.\n\n## 4. Listener Accumulation Across Round-trips\n\n**Symptom**: each chunk emitted N times where N grows with the number of tool round-trips.\n\n**Root cause**: `deliverToolResults` redundantly called `wireStreamEmitter` to attach a fresh listener while the original `sendMessage` listener was still alive (the `sendMessage` await is still pending until `promptComplete`). Removing the duplicate `wireStreamEmitter` registration fixes the duplication; the original listener already covers the response.\n\n**Lesson**: in event-driven session engines, listener attachment must be paired with a clear ownership model. Re-attaching during the same logical turn duplicates events; the simplest fix is to never re-attach.\n\n## 5. Prompt Composition Responsibility Drift\n\n**Symptom**: backend CLI receives raw user text without runtime context tags or conversation history XML.\n\n**Root cause**: the host adapter was supposed to apply `buildInitialPrompt` / `buildRuntimeContextPrompt` via a `cliRuntimeContextBuilder` setter, but the setter was sometimes null or pointed at a different module instance. Result: the host sent `extractLatestUserMessage(context)` raw to `sendMessage`.\n\n**Resolution**: prompt assembly was moved into fleet-core's `session-engine.ts`. The host now calls `sendMessage(handle, { userRequest, history })`, and fleet-core decides between `buildInitialPrompt(history, userRequest)` and `buildRuntimeContextPrompt(userRequest)` based on `session.firstPromptSent`. The `setCliRuntimeContext` setter pattern was deleted.\n\n**Lesson**: when fleet-core owns the prompt assets (`buildRuntimeContextPrompt` lives in `admiral/prompts.ts`), it must also own the prompt assembly. Spreading the responsibility through host setters creates instance-mismatch and timing bugs.\n\n## 6. Two Init Functions Sharing One Concept\n\n**Symptom**: `/resume` cannot restore the backend CLI session — every resume starts fresh.\n\n**Root cause**: `public/runtime.ts:createFleetCoreRuntime` only called the legacy `_shared/agent-runtime`'s `initRuntime`. The new `admiral/agent/internal/session-runtime`'s `initRuntime` was never invoked, so its `sessionStore` stayed null. `getSessionStore()` returned the noop store, `store.get(carrierId)` always returned undefined, and `ensureSession` always built a fresh ACP session.\n\n**Resolution**: `runtime.ts` now calls only the new `initAgentSessionRuntime`. The legacy module was deleted in Wave C of the agent-runtime removal.\n\n**Lesson**: when migrating, two init functions for the same concept is a temporary state that must be closed by deleting one — not by calling both. Calling both creates two stores at the same disk path with separate in-memory caches.\n\n## 7. Conditional Lifecycle Hook Gating\n\n**Symptom**: even after init was wired, `/resume` still fell back to fresh sessions.\n\n**Root cause**: `provider-runtime.ts`'s `pi.on(\"session_start\")` handler called `bindHostSession` only when `event.reason === \"new\" | \"resume\" | \"fork\"`. Other reasons (or absent reason) silently skipped the call. Without `bindHostSession`, `sessionStore.restore` never ran, so `mapFilePath` stayed null. Subsequent `store.set(carrierId, sessionId)` no-op'd because `persist()` short-circuits when `mapFilePath` is null.\n\n**Resolution**: removed the reason gate; `bindHostSession(piSessionId)` runs unconditionally on every `session_start`.\n\n**Lesson**: lifecycle hooks for SSoT initialization should be unconditional. Adding \"obvious\" filters silently disables persistence.\n\n## 8. Type Migration Without Round-trip Field Audit\n\n**Symptom**: ACP CLI receives the message but the prompt looks \"thin\" — no system-reminder block.\n\n**Root cause**: when reshaping `ExecuteOptions`/`ExecuteResult` into `CarrierExecuteOptions`/`CarrierExecResult`, the `connectSystemPrompt` and `model` fields had to round-trip through every callsite. A missed field at any point disables a downstream behavior silently because the type is `string | null | undefined`.\n\n**Lesson**: type migrations should include a \"field round-trip audit\" that grep-checks every property name from the legacy type against the new type's call sites.\n\n## Common Pattern: Static Grep Gates as Regression Insurance\n\nAfter each fix, a corresponding static grep entered the QA gate:\n\n- `rg \"FleetToolRegistryHostPorts|noopToolPorts|readonly now\"` (ports pattern eradicated)\n- `rg \"globalThis.__pi_unified_agent\"` (legacy globalThis keys removed)\n- `rg \"_shared/agent-runtime|admiral/agent-runtime\"` (legacy import paths)\n- `rg \"AgentStatus|ColStatus|ColBlock\" packages/fleet-core/src` (status/block types host-only)\n- `test ! -f packages/fleet-core/src/admiral/_shared/agent-runtime.ts` (file deletion proof)\n\nThese gates are now part of `.fleet/plans/agent-runtime-removal.md` Wave D acceptance criteria.
