## Overview

코딩 에이전트 사용 중 TUI 세션 선택기(Session Selector)에 의미 없는 빈 세션(`(no messages)`)이 누적되는 문제를 구조적으로 해결하기 위한 결정입니다. 세션의 영속화 시점을 "의미 있는 상호작용" 이후로 지연시키고 식별 체계를 일원화하여 사용자가 실제 작업 이력에만 집중할 수 있는 환경을 제공합니다.

## Problem

기존 상태에서는 사용자가 에이전트를 초기화하거나 새 세션을 열기만 해도 디스크에 세션 파일이 즉시 생성되었습니다. 이로 인해 세션 선택기가 실제 대화 내용이 없는 `(no messages)` 라벨의 유령 세션들로 가득 차게 되어, 사용자가 과거의 유의미한 작업 이력을 식별하는 데 큰 인지적 부하(Cognitive Debt)와 마찰이 발생했습니다.

이 문제의 구조적 원인은 세션 영속화 트리거가 "사용자와 에이전트 간의 첫 번째 유의미한 왕복 대화"라는 단일 지점으로 통합되지 않고, 연결(Connect), 상태 설정, 종료 등 여러 시스템 이벤트 경로에 산발적으로 존재했기 때문입니다.

## Goals

- 실제 작업 내용이 없는 세션이 세션 선택기에 노출되는 현상을 원천 차단
- 호스트 환경과 그랜드 플릿 간의 세션 식별 체계 단일화를 통한 추적 일관성 확보
- 세션 목록의 가독성을 회복하고 작업 이력 관리의 품질 보장
- 임시방편(사후 삭제 등)이 아닌 구조적 개선을 통한 시스템 신뢰도 향상

## Non-Goals

- 이미 디스크에 생성된 기존 빈 세션 파일들을 자동으로 삭제하는 기능(사후 Sweep) 제공
- 세션 파일은 생성하되 UI에서만 필터링하여 숨기는 방식의 우회
- 에이전트 초기화 실패 시의 복구를 위한 별도의 세션 재시도 로직 구현

## User Stories

**As a** 개발자, **when** 코딩 에이전트 세션을 새로 생성하거나 여러 에이전트를 동시에 초기화했을 때, **then** 실제로 대화를 시작하기 전까지는 세션 선택기에 불필요한 항목이 늘어나지 않아야 합니다.

## Functional Requirements

- **영속화 임계값 제어**: 사용자와 에이전트 간에 최소 한 번의 유의미한 메시지 왕복(User request → Assistant response)이 완료된 세션에 한해서만 영속적 저장을 허용합니다.
- **식별자 단일화 계약**: 모든 세션은 생성 시점부터 종료 시점까지 단일한 세션 식별자를 유지하며, 그랜드 플릿 등 외부 등록 환경에서도 가상 ID 대신 이 식별자를 공통 분모로 사용합니다.
- **상태 무결성 보장**: 세션 상태 업데이트 시마다 현재 세션의 고유 토큰을 검증하여, 교차 세션 간의 상태 오염이나 잘못된 시점의 커밋을 차단합니다.

## Acceptance Criteria

- [ ] 새 세션을 생성한 후 아무런 메시지를 입력하지 않고 종료했을 때, 다시 에이전트를 실행해도 세션 선택기에 해당 세션이 나타나지 않는다.
- [ ] 여러 에이전트를 병렬로 초기화하는 상황에서도 실제 대화가 발생하지 않은 세션에 대해서는 디스크 파일이 생성되지 않는다.
- [ ] 첫 번째 메시지 응답이 완료된 직후부터는 해당 세션이 세션 선택기 목록에 정상적으로 노출된다.
- [ ] 그랜드 플릿 환경에서 세션을 추적할 때 별도의 가상 ID 없이 실제 세션 ID만으로 일관된 상태 확인이 가능하다.
