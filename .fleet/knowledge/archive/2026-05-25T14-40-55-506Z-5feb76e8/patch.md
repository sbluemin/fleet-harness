외부 CLI 3종의 spawn 시 sub-agent 주입 메커니즘 비교\n\n## Overview\n\nFleet이 지휘하는 외부 CLI 3종(**Claude Code**, **Codex CLI**, **OpenCode**)이 프로세스를 spawn할 때 **인자(argument)로 커스텀 sub-agent를 주입**하는 방식을 비교한 정찰 노트다. 세 CLI 모두 \"이미 등록된 에이전트를 이름으로 선택\"하는 채널은 가지지만, **휘발성 인라인 정의를 인자로 직접 받는 것은 Claude Code뿐**이며 Codex와 OpenCode는 파일 기반 정의를 우회 채널로 보완한다.\n\n## 결론 요약\n\n| 항목 | Claude Code | Codex CLI | OpenCode |\n|---|---|---|---|\n| 인라인 sub-agent 정의 플래그 | **`--agents '<JSON>'`** ✅ | 없음 ❌ | 없음 ❌ |\n| 이름으로 선택 플래그 | `--agent <name>` | `-p, --profile <name>` (프로필) | `--agent <name>` |\n| 정의 파일 위치 | `.claude/agents/*.md` (frontmatter) | `~/.codex/agents/*.toml` | `.opencode/agents/*.md` 또는 `opencode.json` |\n| 세션 한정 휘발성 정의 | 직접 지원 | 미지원 (`-c` 비공식 우회만) | 미지원 (env 우회) |\n| 공식 env 인라인 우회 | (불필요) | 없음 | **`OPENCODE_CONFIG_CONTENT`** ✅ |\n| CLI 플래그로 sub-agent 강제 호출 | Task 도구 `subagent_type` | 불가 (자연어 위임만) | `--agent <name>`으로 가능 |\n\n## Claude Code — 유일하게 인라인 정의를 인자로 받는 CLI\n\n`--agents <json>` 플래그가 핵심.\n\n```bash\nclaude --agents '{\n  \"code-reviewer\": {\n    \"description\": \"Expert code reviewer\",\n    \"prompt\": \"You are a senior code reviewer...\",\n    \"tools\": [\"Read\", \"Grep\", \"Glob\", \"Bash\"],\n    \"model\": \"sonnet\"\n  }\n}'\n```\n\n- **세션 한정 휘발성**: 디스크에 저장되지 않고 해당 spawn 세션에서만 존재.\n- **다중 정의**: JSON 객체의 top-level 키 하나가 sub-agent 1개.\n- **필드 셋**: `description`, `prompt`, `tools`, `disallowedTools`, `model`, `permissionMode`, `mcpServers`, `hooks`, `maxTurns`, `skills`, `initialPrompt`, `memory`, `effort`, `background`, `isolation`, `color` — `.claude/agents/*.md` frontmatter와 동일 스펙.\n- **단수형** `--agent <name>`은 별개로, 이미 등록된 에이전트를 세션 기본값으로 선택만 한다.\n\n공식 문서: https://code.claude.com/docs/en/sub-agents\n\n## Codex CLI — 파일 기반 정의만, CLI 인라인 채널 없음\n\n```bash\ncodex -p my-profile          # 미리 정의된 프로필 선택\ncodex -c model='\"o3\"'         # 임의 TOML 키 override\n```\n\n- `--agents`/`--agent`/`--persona`/`--sub-agent`/`--system-prompt`/`--instructions` **모두 부재**.\n- Sub-agent 정의는 **파일만**:\n  - `~/.codex/agents/<name>.toml` (개인) 또는 `.codex/agents/<name>.toml` (프로젝트)\n  - 필수: `name`, `description`, `developer_instructions`\n- **호출 방식**: \"Codex only spawns a new agent when you explicitly ask it to do so\" — 자연어 프롬프트로 메인 에이전트가 위임할 뿐, CLI 플래그로 특정 sub-agent를 강제 호출하는 채널이 없다.\n- **비공식 우회**: `-c 'agents.X.developer_instructions=\"...\"'` 로 TOML 키를 override 가능하나 sub-agent 정의 경로로 권장되지 않음.\n\n공식 문서: https://developers.openai.com/codex/subagents, https://developers.openai.com/codex/cli/reference\n\n## OpenCode — 이름 선택은 가능, 인라인은 env로 우회\n\n```bash\nopencode --agent my-agent                              # 이름 룩업만\nopencode run --agent my-agent \"메시지\"                  # run 서브커맨드 동일\n```\n\n- `--agent <name>`은 **이름 룩업만** 수행 (`pickAgent()`). 미발견 시 default 폴백.\n- `--agents` (인라인 JSON) **부재** — Claude Code 등가물 없음.\n- Sub-agent 정의는 파일 기반:\n  - Markdown: `~/.config/opencode/agents/<name>.md` (글로벌) 또는 `.opencode/agents/<name>.md` (프로젝트). YAML frontmatter(`description`, `mode: subagent|primary|all`, `model`, `temperature`, `permission`) + 본문 시스템 프롬프트.\n  - JSON: `opencode.json`의 `\"agent\": { \"<name>\": { ... } }` 키.\n- **`opencode agent create`** 서브커맨드는 디스크에 마크다운을 생성할 뿐 메모리 동적 등록 아님.\n\n### 인라인에 가장 근접한 공식 우회 — 환경변수\n\n| env | 용도 |\n|---|---|\n| `OPENCODE_CONFIG` | 커스텀 config 파일 경로 |\n| `OPENCODE_CONFIG_DIR` | 커스텀 config 디렉터리 |\n| **`OPENCODE_CONFIG_CONTENT`** | **Runtime overrides** — config JSON 문자열 직접 주입 |\n\n실용 패턴:\n\n```bash\n# 패턴 A — env로 agent 정의 인라인 주입 후 이름 참조\nOPENCODE_CONFIG_CONTENT='{\"agent\":{\"tempagent\":{\"description\":\"...\",\"prompt\":\"...\"}}}' \\\n  opencode run --agent tempagent \"메시지\"\n\n# 패턴 B — 임시 디렉터리에 파일 작성 후 --dir로 지정\nmkdir -p /tmp/oc/.opencode/agents\ncat > /tmp/oc/.opencode/agents/tempagent.md <<'EOF'\n---\ndescription: ...\nmode: primary\n---\n당신은 ...\nEOF\nopencode run --dir /tmp/oc --agent tempagent \"메시지\"\n```\n\n공식 문서: https://opencode.ai/docs/agents/, https://opencode.ai/docs/cli/, https://opencode.ai/docs/config/\n\n## Fleet 운영 관점의 시사점\n\n- **Claude Code 기반 카리어**는 spawn 인자만으로 페르소나/도구 스코프/모델/effort를 한 호출에 묶어 정의·주입할 수 있어 가장 유연하다. 페르소나 외부화(→ `prd-carrier-persona-extraction`) 결과를 그대로 `--agents` JSON으로 직렬화할 수 있다.\n- **Codex 기반 카리어**는 파일 기반 사전 배포가 사실상 유일한 정공법이다. 휘발성 페르소나가 필요하다면 `~/.codex/agents/` 또는 `.codex/agents/` 디렉터리에 spawn 직전 파일을 쓰는 부트스트랩 단계가 필수다. `-c` override는 도구 스코프나 모델 정도의 보조 튜닝에 한정 권장.\n- **OpenCode 기반 카리어**는 `OPENCODE_CONFIG_CONTENT` env로 깔끔한 휘발성 주입이 가능하므로 Codex보다 한 단계 더 자연스러운 우회 경로를 가진다. spawn 시 env를 합성해서 페르소나를 한 번에 주입한 뒤 `--agent <name>`으로 참조하는 패턴이 권장된다.\n\n## 검증 출처\n\n- 로컬 `claude --help`, `codex --help`, `opencode --help`, `opencode run --help` (2026-05-25 캡처)\n-
