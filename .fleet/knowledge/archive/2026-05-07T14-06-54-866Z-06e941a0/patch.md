--help)","tags":["fleet-wiki-web","cli","onboarding","current"],"created":"2026-05-07T14:06:54.866Z","updated":"2026-05-07T14:06:54.866Z","version":1,"body":"## Summary\n\n`fleet-wiki`는 현재 워크스페이스의 `.fleet/knowledge` 위키를 브라우저로 열기 위한 detached HTTP 서버 CLI다. cwd별로 독립 lockfile을 잡아 같은 머신에서 여러 워크스페이스를 동시에 띄울 수 있고, 단일 워크스페이스 안에서는 1개 인스턴스만 살아 있는다. 본 엔트리는 명령어 옵션, 환경변수, 수명주기, 안전장치, 트러블슈팅을 처음 사용자가 따라할 수 있는 형태로 정리한다.\n\n본 문서는 CLI 진입점(`fleet-wiki` 명령) 사용법만 다룬다. 위키 안쪽의 9개 MCP 툴(`wiki_orient`, `wiki_briefing`, `wiki_ingest` 등)은 별도 엔트리에서 다룬다.\n\n## Quick Start\n\n```bash\n# 1) 워크스페이스 루트에서 fleet-wiki 띄우기 (브라우저 자동 오픈)\nfleet-wiki\n\n# 2) 포트/호스트 지정해서 띄우기\nfleet-wiki --host 127.0.0.1 --port 4040\n\n# 3) 환경변수로 지정\nFLEET_WIKI_PORT=4040 fleet-wiki\n\n# 4) 같은 cwd에서 구동 중인 서버를 안전하게 종료\nfleet-wiki --stop\n\n# 5) 도움말\nfleet-wiki --help\n```\n\n`fleet-wiki`는 `.fleet/knowledge` 디렉토리가 존재하는 워크스페이스에서 실행해야 한다. 처음 실행하면 schema를 자동 부트스트랩한다.\n\n## Commands & Options\n\n| 옵션 | 인자 | 설명 |\n|---|---|---|\n| `--host` | `<host>` | 바인드 호스트. 기본 `127.0.0.1`. 와일드카드(`0.0.0.0`)는 브라우저/healthcheck URL 계산 시 loopback으로 정규화된다. |\n| `--port` | `<port>` | 서버 포트. 미지정 시 사용 가능한 free port 자동 선택. |\n| `--stop` | — | 현재 cwd에서 구동 중인 fleet-wiki 서버를 graceful 종료(SIGTERM → 200ms → SIGKILL fallback). 종료 후 lock 파일을 정리한다. |\n| `--help` | — | 옵션·환경변수·예시를 출력하고 즉시 종료. |\n\n미등록 옵션(`--foo` 등)은 `process.exit(1)`로 즉시 거부된다.\n\n## Environment Variables\n\n| 변수 | 효과 |\n|---|---|\n| `FLEET_WIKI_PORT` | 기본 포트. `--port`가 우선. |\n| `FLEET_WIKI_HOST` | 기본 호스트. `--host`가 우선. |\n| `FLEET_WIKI_NO_AUTO_RESTART` | `1`로 설정 시 stale 빌드 lock을 재시작하지 않고 기존 서버를 그대로 재사용한다. 기본값은 자동 재시작. |\n\n## Server Lifecycle & Lock Layout\n\n`fleet-wiki`는 cli 프로세스에서 곧바로 HTTP를 띄우지 않고 별도의 detached `server.mjs`를 spawn한다. 그래서 cli는 lock 파일이 health 응답을 줄 때까지 기다렸다가 브라우저를 연 뒤 즉시 종료한다.\n\nLock 파일 경로 규칙:\n\n```\n${os.tmpdir()}/fleet-wiki-${uid}/fleet-wiki-${sha1(cwd).slice(0,12)}.lock\n```\n\n- macOS의 경우 `os.tmpdir()`는 `/var/folders/.../T/`이며, `/tmp`가 아니다.\n- 디렉토리 모드 `0700`, 파일 모드 `0600`, 생성은 `O_CREAT | O_EXCL | O_WRONLY`로 atomic.\n- Symbolic link로 만들어진 lock은 lstat 검사로 거부 후 제거된다.\n\nLock JSON 스키마:\n\n```json\n{\n  \"pid\": 12345,\n  \"port\": 4040,\n  \"cwd\": \"/abs/workspace/path\",\n  \"startedAt\": \"2026-05-07T14:02:06.325Z\",\n  \"host\": \"127.0.0.1\"\n}\n```\n\n같은 cwd에서 두 번째 `fleet-wiki`를 실행하면:\n\n1. 기존 pid가 죽었으면 lock을 정리하고 재시도.\n2. 기존 pid 생존 + health OK + `FLEET_WIKI_NO_AUTO_RESTART` → 기존 서버를 재사용하고 브라우저만 다시 연다.\n3. 기존 pid 생존 + health OK + 빌드 산출물보다 lock이 오래됨(stale) → SIGTERM으로 종료 후 새 빌드로 재기동(`isLockTrustworthyForRestart()` 통과 시).\n4. 기존 pid 생존 + health 실패 → 짧은 폴링 후 그래도 실패하면 에러.\n\n## Safety Guards (--stop)\n\n`--stop`은 cwd 격리와 PID 위생 검증을 모두 통과한 경우에만 실제 시그널을 보낸다.\n\n| 가드 | 동작 |\n|---|---|\n| **cwd 일치 검증** | lock JSON의 `cwd`와 현재 `process.cwd()`가 일치하지 않으면 `exit 1`로 거부. 다른 워크스페이스의 lock을 절대 건드리지 않는다. |\n| **pid 정수성 검증** | `Number.isInteger(pid) && pid > 1`. `pid:0`은 `process.kill(0, signal)` 세맨틱상 프로세스 그룹 전체 살해 위험이 있으므로 차단. |\n| **dead PID 자동 정리** | `!isProcessAlive(pid)`이면 우리 cwd lock임이 확인된 경우에 한해 stale lock을 제거하고 `exit 0`. |\n| **idempotent** | lock이 없거나 디렉토리가 없으면 `exit 0`(스크립트/CI 안전). |\n| **시그널 패턴** | 살아있는 프로세스 종료는 `SIGTERM` → 200ms 대기 → `SIGKILL` fallback. |\n\n종료 시 다른 워크스페이스의 lock 파일은 같은 디렉토리에 있어도 손대지 않는다.\n\n## Troubleshooting\n\n### \"lock에 비정상 PID가 기록되어 있습니다(pid=...)\"\n\n`--stop`이 손상된 lock을 발견했다는 뜻이다. 자동 정리하지 않고 사람의 확인을 요구한다. lock 파일을 직접 열어 내용을 확인한 뒤 안전하다고 판단되면 수동으로 삭제하라.\n\n```bash\ncat \"$(node -e \"const c=require('crypto'),os=require('os'),p=require('path');console.log(p.join(os.tmpdir(),'fleet-wiki-'+process.getuid(),'fleet-wiki-'+c.createHash('sha1').update(process.cwd()).digest('hex').slice(0,12)+'.lock'))\")\"\n```\n\n### \"현재 CWD와 lock cwd가 다릅니다\"\n\n같은 머신의 다른 워크스페이스가 우연히 같은 lock 슬롯을 점유한 매우 드문 경우거나, lock 파일이 다른 워크스페이스에서 복사된 경우다. `--stop`은 이 경우 어떤 동작도 하지 않고 종료한다. 해당 워크스페이스에서 직접 `--stop`을 실행하라.\n\n### \"Fleet Wiki 서버(pid=...)는 이미 종료되어 있습니다\"\n\n프로세스가 이미 종료된 후 lock 파일만 남아있던 케이스다. `--stop`이 자동으로 lock을 정리하고 `exit 0`으로 종료한다. 다음 실행은 정상 진행된다.\n\n### 브라우저가 열리지 않을 때\n\ncli는 OS 기본 명령(macOS `open`, Linux `xdg-open`, Windows `start`)으로 브라우저를 spawn한다. `BROWSER` 환경변수로는 우회되지 않으며, 헤드리스 환경이면 lock 파일에서 직접 URL(`http://127.0.0.1:${port}`)을 확인해 사용하라.\n\n### Stale 빌드 자동 재시작이 막힐 때\n\n빌드 산출물(`dist/server.mjs`)을 새로 빌드한 뒤 동일 cwd에서 다시 `fleet-wiki`를 실행하면 기존 서버가 SIGTERM 후 새 빌드로 재기동된다. 자동 재시작이 부담스러우면 `FLEET_WIKI_NO_AUTO_RESTART=1`로 비활성화한 뒤 수동 `--stop` → 재기동을 사용하라.\n\n## Security Boundaries (요약)\n\n- 서버는 `127.0.0.1`에만 바인드된다. CORS `*` 미허용.\n- POST 요청은 `/api/queue/:patchId/approve|reject`만 허용되며 `Origin: http://127.0.0.1:${port}`와 정확히 일치해야 한다.\n- 마크다운은 DOMPurify로 sanitize한 뒤에만 렌더링되며 `javascript:`, `data:` 스킴은 차단된다.\n- 자세한 항목은 packages/fleet-wiki-web/AGENTS.md 의 \"Security Boundaries\" 섹션을 참조하라.\n\n## See Also\n\n- 위키 안쪽 MCP 도구 사용법: [[wiki:fleet-wiki-9-tools]]\n- 읽기 흐름(orient → briefing → resolve → read): [[wiki:fleet-wiki-read-flow]]\n- 쓰기 흐름(ingest → patch_queue → compile_source): [[wiki:fleet-wiki-write-flow]]","rawSourceRef":"raw/2026-05-07-fleet-wiki-cli-onboarding-source-5a58e05e.md"}
