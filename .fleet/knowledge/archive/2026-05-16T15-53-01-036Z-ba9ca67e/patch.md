도입","tags":["coding-agent","prompts","slash-command","naming-convention","ux","shipped"],"created":"2026-05-16T15:53:01.036Z","updated":"2026-05-16T15:53:01.036Z","version":1,"body":"## Overview\n본 문서는 `coding-agent`의 prompt template 호출 방식을 기존의 bare `/{name}` 형식에서 `/prompt:{name}` 접두사 기반 형식으로 변경하는 사양을 정의한다. 이는 자원 종류별 명명 컨벤션을 통일하고, 슬래시 명령 팔레트에서의 시각적 식별성을 강화하여 사용자의 인지 부채를 해소하는 것을 목적으로 한다.\n\n## Problem\n- **호출 컨벤션의 비대칭성**: 기존 시스템에서 skill은 `/skill:{name}` 접두사를 사용했으나, prompt template은 접두사 없이 `/{name}` 형식을 사용했다. 이로 인해 사용자는 자원 종류마다 접두사 사용 여부를 개별적으로 기억해야 하는 불편함이 있었다.\n- **시각적 식별성 부재**: 자동완성 팔레트에서 builtin command, extension command, prompt template이 모두 동일한 `/{name}` 패턴으로 섞여 노출되어, 사용자가 특정 명령이 어떤 종류의 자원(템플릿인지, 도구인지 등)인지 즉각적으로 파악하기 어려웠다.\n- **네임스페이스 충돌 리스크**: prompt template 이름이 다른 builtin command나 skill 접두사 패턴과 겹칠 경우, 의도하지 않은 명령이 실행되거나 템플릿이 호출을 가로채는(shadowing) 등 네임스페이스 충돌 가능성이 상존했다.\n\n## Goals\n- **명명 컨벤션 일관성 확보**: prompt template 호출 시 `/prompt:` 접두사를 도입하여 skill(`/skill:`)과 대칭적인 구조를 형성한다.\n- **사용자 인지 부채 해소**: \"모든 외부 등록 자원(skill/prompt)은 접두사를 가진다\"는 명확한 규칙을 제공하여 사용자의 학습 및 기억 비용을 절감한다.\n- **자원 식별성 강화**: 자동완성 목록에서 `prompt:` 접두사를 통해 해당 항목이 템플릿임을 즉시 시각적으로 인지할 수 있도록 한다.\n- **네임스페이스 격리**: 고유 접두사를 통해 builtin command와 prompt template 간의 이름 충돌 가능성을 원천적으로 차단한다.\n\n## Non-Goals\n- **Extension Command 변경**: 개별 extension이 등록한 커스텀 명령(`/{cmd}`)은 기존의 bare 형식을 유지한다. 본 변경은 prompt template 자원에만 한정된다.\n- **데이터 모델 불변**: prompt template의 내부 데이터 구조, 로딩 방식, 디스커버리 로직 등 기능적 구현은 변경하지 않는다.\n- **기존 기능 제거**: 기존 템플릿 기능을 축소하지 않으며 오직 호출 \"표면\"의 명칭 규약만 조정한다.\n\n## User Stories\n- **As a** 사용자, **when** 에디터에서 `/`를 입력할 때, **then** `prompt:review`와 같이 명확한 접두사가 붙은 제안을 보고 이것이 내가 작성한 템플릿임을 즉시 알 수 있다.\n- **As a** 사용자, **when** 새로운 prompt template을 만들 때, **then** \"이 이름이 내장 명령인 `/model`과 겹치면 어쩌지?\"라는 걱정 없이 자유롭게 이름을 지을 수 있다.\n- **As a** 캐리어, **when** 시스템 도움말에서 prompt 호출법을 배울 때, **then** skill과 동일한 패턴의 규칙을 확인하고 일관성 있게 기능을 활용할 수 있다.\n\n## Functional Requirements\n- **호출 패턴 변경**: 슬래시 명령 확장 시 bare name 대신 `prompt:{name}` 문자열을 매칭 기준으로 사용한다.\n- **RPC 인터페이스 동기화**: `get_commands`와 같은 제어 평면 API의 응답에서 prompt template의 `name` 필드에 `prompt:` 접두사를 포함하여 반환한다.\n- **자동완성 연동**: TUI 및 RPC 클라이언트가 사용하는 자동완성 후보 리스트에 접두사가 포함된 이름을 제공한다.\n\n## Acceptance Criteria\n- [ ] 에디터에서 `/prompt:{name}` 입력 시 해당 템플릿이 정상적으로 확장되는가?\n- [ ] 기존의 bare `/{name}` 형식으로 입력 시 템플릿으로 확장되지 않고 일반 텍스트(또는 존재하지 않는 명령)로 처리되는가?\n- [ ] 자동완성 목록에서 prompt template들이 `prompt:` 접두사를 달고 노출되는가?\n- [ ] `get_commands` RPC 응답 데이터 내 prompt 항목의 `name`이 `prompt:`로 시작하는가?\n\n## Related\n- [[wiki:prd-coding-agent-scoped-models-removal]]\n-
