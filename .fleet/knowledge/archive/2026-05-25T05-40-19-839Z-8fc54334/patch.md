{"id":"prd-fleet-menu-t3-full","title":"PRD: Fleet Menu T3 풀 구현 (Authentication / Wiki Server / Diagnostics / About)","tags":["prd","fleet-menu","mission-control","panel-stack","auth","wiki-server","diagnostics","about","fleet-infra-log"],"created":"2026-05-25T05:40:19.839Z","updated":"2026-05-25T05:40:19.839Z","version":1,"templateId":"prd","body":"## Overview\n\n본 PRD는 `cli-args→preset` 사조(전신: `prd-cli-argv-to-preset`)에서 T3 메뉴(Fleet Menu)가 navigation stub 상태로 남아 있어 Enter 입력 시 아문 동작도 일어나지 않던 \"기능이 안 됨\" UX 실패를 해결하기 위한 풀 구현을 정의한다. 6개 wave로 분할 개발되며, 4개 패널(Authentication, Wiki Server, Diagnostics, About)의 책임 범위, 아키텍처 결정, 보안 강화 항목, 그리고 후속 확장 가능성을 포괄한다.\n\n## Problem\n\nMission Control `m` 진입 시 Fleet Menu가 4개 항목(Auth, Wiki, Diagnostics, About)을 렌더하지만, 선택 후 Enter를 눌러도 실제 기능이 동작하지 않았다. 이는 단순히 UI 누락이 아니라, 사용자가 설정·서버·진단 정보·버전 확인이라는 기대를 UI로 받아들인 뒤 실망하는 \"false promise\" UX 결함이다. Options Drawer(T2)는 이미 실제 동작했으므로 T3 메뉴의 신뢰도 하락은 전체 TUI 일관성에도 영향을 미친다.\n\n추가로, Diagnostics 등 일부 패널이 직접 host UI에서 파일 시스템을 읽으려는 경향이 있었는데, 이는 `fleet-infra`가 소유하는 I/O Gateway Contract를 위반하는 구조적 문제다.\n\n## Goals\n\n1. Fleet Menu 4개 항목을 기능하는 패널로 완전히 구현한다.\n2. 패널 전환·빵부스러기·입력 모달 등 공통 인프라를 재사용 가능하게 만든다.\n3. `fleet-infra` public API를 통해 host UI의 직접 fs read를 제거하고 Gateway Contract를 준수한다.\n4. 모든 패널이 Options Drawer와 동일한 full welcome banner를 유지한다.\n5. 보안 취약점(API key 노출, 임의 파일 탐색, 터미널 제어 문자 주입)을 사전에 차단한다.\n\n## Non-Goals\n\n- T1 Welcome Chips 동작 변경\n- T2 Options Drawer 기능 추가\n- argv 1회성 flag의 label 누출 방지(선행 사조에서 이미 해결)\n- `fleet-wiki`, `fleet-wiki-ui`, carrier/unified-agent의 직접 변경\n- Cursor Sync를 Diagnostics 내 중복 노출\n- named preset 도입(후속 사조로 이관)\n- 로그 뷰어의 rotate/delete 등 mutation 기능\n\n## User Stories\n\n- 운용자는 Fleet Menu에서 API key를 조회·저장·삭제할 수 있고, 입력 중 password masking이 적용된다.\n- 운용자는 Wiki Server 패널에서 Enter로 서버를 켜고 끌 수 있으며, `P` 키로 포트를 바꿀 수 있다.\n- 운용자는 Diagnostics 패널에서 최근 로그를 안전하게 읽고, data dir 경로를 확인하며, 전체 preset을 초기화할 수 있다.\n- 운용자는 About 패널에서 버전·채널·활성 carrier 수·위키 엔트리 수·패치 큐 수를 확인한다.\n\n## Functional Requirements\n\n### FR-1: 공통 Panel Infrastructure (Wave 1)\n\n- PanelStack: LIFO push/pop, depth 기반 breadcrumb 자동 생성\n- Native input modal: text / password / numeric / confirm 4가지 타입 지원\n- Password 타입은 입력 문자를 마스킹 표시한다\n- Confirm 타입은 \"Are you sure?\" 단순 yes/no 흐름을 제공한다\n- Async submit 중 `onRenderRequest` 콜백으로 rerender를 트리거한다\n\n### FR-2: Authentication Panel (Wave 2)\n\n- `@dotobokuri/fleet-infra/auth` public API를 재사용한다\n- 현재 저장된 provider와 API key 존재 여부를 표시한다\n- `Enter`로 API key 입력 모달 진입, 저장 시 `setApiKey` 호출\n- `D` 키로 삭제 시 confirm modal 한 번 더 거친 뒤 삭제\n- API key 문자열은 렌더링·로깅 시 전부 mask 처리(마지막 4자리만 노출)\n\n### FR-3: Wiki Server Panel (Wave 3)\n\n- Detached background subprocess로 wiki 서버를 실행한다\n- `spawn(process.execPath, [...], { detached: true, stdio: \"ignore\" })` + `unref()`\n- Enter 토글: 실행 중이면 종료, 종료 상태면 시작\n- `P` 키로 port 입력 모달 진입, 유효 범위 1024–65535\n- Actual listen port는 lock-file polling로 반영한다\n- 서버 discovery는 panel이 관리하는 서버 프로세스만 인식한다(외부 프로세스는 후속 결정)\n\n### FR-4: Diagnostics Panel (Wave 4)\n\n- Log viewer: `@dotobokuri/fleet-infra/log/reader` public API 사용\n- Host UI의 직접 fs read 금지 원칙 준수\n- Log read 보안: `O_NOFOLLOW`, `fstatSync(fd)`, size cap(256KiB), line cap(200줄)\n- 데이터 디렉터리 경로 표시\n- Reset preset: 전체 startup preset 초기화(단, 그룹 D 분리 보존) + confirm modal\n- System info: Node 버전, 플랫폼, 아키텍처\n- Cursor Sync 항목은 노출하지 않는다(중복 금지)\n- 동적 외부 문자열(log/env/path)은 `sanitizeTerminalText`로 ANSI/OSC/control + LF/CR strip\n\n### FR-5: About Panel (Wave 5)\n\n- Full FLEET ASCII banner + 버전/채널 표시\n- 3-count 고정: 활성 carrier 수, wiki 엔트리 수, 패치 큐 대기 수\n- 4번째 count는 발명 금지(후속에 자연스럽게 추가될 때까지)\n- Docs URL placeholder 유지(실제 URL 확정 시 교체)\n- Node 버전, 플랫폼, 아키텍처 정보\n\n### FR-6: 아키텍처·UX 일관성\n\n- PanelStack + welcome banner shell 합성: panel 모드에서도 full banner 유지(Options Drawer와 동일)\n- 2단계 navigation: 메뉴 목록 → 패널 세부 화면\n- `Esc` 단계별 복귀: 패널 내부 상태 → 메뉴 목록 → Mission Control 본체\n\n### FR-7: 신규 fleet-infra public API\n\n- `@dotobokuri/fleet-infra/log/reader` 추가\n- `readRecentLogFiles({ category?, limit })` 인터페이스\n- AGENTS.md I/O Gateway Contract 준수\n\n### FR-8: 보안 강화\n\n- API key masking(렌더·로그 전역)\n- `sanitizeTerminalText`: ANSI escape/OSC sequence/control 문자 + CR/LF strip\n- Log read: `O_NOFOLLOW` + `fstat` + size cap\n- Port validation: 1024–65535 numeric 범위\n- Detached subprocess: no-IPC spawn, `stdio: \"ignore\"`, `unref()`\n\n## Acceptance Criteria\n\n- [ ] `m` 메뉴 진입 후 4개 항목 모두 Enter 시 실제 패널로 진입한다.\n- [ ] Auth 패널에서 API key 저장·삭제가 동작하고 password 입력 시 마스킹된다.\n- [ ] Wiki 패널에서 Enter 토글로 서버가 켜지고 꺼지며, port 변경이 1024–65535 범위에서만 허용된다.\n- [ ] Diagnostics 패널에서 로그를 읽을 수 있고, reset preset 시 confirm modal을 거친다.\n- [ ] About 패널에서 full banner와 3-count가 표시된다.\n- [ ] Options Drawer와 Fleet Menu 모두 동일한 full banner를 사용한다(compact banner 없음).\n- [ ] `fleet-cli` 전체 test/build 통과.\n- [ ] `fleet-infra` 전체 test/typecheck/build 통과.\n\n## Open Questions\n\n- 사용자가 외부에서 `fleet wiki`로 띄운 서버를 panel에서 인식해야 하는 요구가 발생하면, PID 파일·포트 스캔 기반 discovery 메커니즘 도입이 필요하다. 현재는 panel 관리 서버만 인식한다.\n- Log viewer가 향후 mutation(rotate/delete)을 지원하려면 별도 PRD가 필요하다.\n- Input modal이 향후 multi-line text나 select picker 등 확장 위젯이 필요해지면 별도 wave로 분리한다.\n- named preset 도입 시점은 후속 사조로 이관된다.\n- About의 4번째 count는 자연스럽게 생기는 데이터 소스가 확보될 때 추가한다(발명 금지).\n- Docs URL 확정 시 About placeholder를 실제 링크로 교체한다.\n\n##
