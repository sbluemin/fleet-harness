Fleet이 Codex spawn 시점에 custom subagent 역할을 등록하려면 글로벌 role TOML 파일을 작성하고, Codex 실행 인자에 `-c agents.<roleKey>.description=...` 및 `-c agents.<roleKey>.config_file=/absolute/path/to/<roleKey>.toml`을 주입해야 한다.\n\n## 결론 요약\n\n| 항목 | Claude Code | Codex CLI | OpenCode |\n|---|---|---|---|\n| 인라인 subagent 정의 | `--agents <JSON>` 지원 | 직접 인라인 정의 없음 | 직접 인라인 정의 없음 |\n| spawn 시점 커스텀 정의 | JSON 인자로 전달 | role TOML 파일 + `-c agents.<role>.config_file` | config/env 또는 파일 기반 |\n| 역할 호출 방식 | Task 도구의 subagent type | Codex 내부 `spawn_agent(agent_type=...)` | `--agent <name>` 이름 선택 |\n| Fleet 권장 패턴 | 기존 Claude native path 유지 (`--agents` 인라인 JSON) | 글로벌 TOML 생성 후 Codex argv에 config override 주입 | 별도 wave에서 env/config 기반 검토 |\n\n## Codex 적용 방안\n\n### Role Key 규칙\n\nCodex subagent의 role key는 bare carrier id를 그대로 사용한다. 이전 버전의 `fleet_` 접두사는 완전히 제거됐다.\n\n- 예시: carrier id가 `vanguard`이면 role key는 `vanguard`, 파일명은 `vanguard.toml`, TOML `name` 필드는 `\"vanguard\"`, argv는 `-c agents.vanguard.*`\n- role key는 dot path 파싱 문제를 피하도록 영문/숫자/underscore로 제한한다.\n- **Reserved-name 가드**: Codex built-in role인 `default`, `explorer`, `worker`, `awaiter`와 동일한 carrier id가 있으면 injection 시도 시 에러로 차단한다. 이 가드는 유지된다.\n\n### 저장 위치 및 I/O 소유\n\n- 모든 role TOML은 글로벌 Fleet data dir 하위 `~/.fleet/codex-agents/<roleKey>.toml`에 저장한다.\n- 디렉터리 권한 `0700`, 파일 권한 `0600`.\n- 파일 I/O(write/remove/path 관리)는 `fleet-carriers` store가 단독으로 소유한다.\n- 세션별 UUID 서브디렉터리, orphan sweep, per-session cleanup은 사용하지 않는다. subagent mode가 enabled인 동안 파일을 유지하고, disable 시 해당 `<roleKey>.toml` 파일만 제거한다.\n\n### Native=true 처리\n\ncarrier가 `native=true`로 설정된 경우 injection을 전체 skip한다. TOML 파일을 생성하지 않고 argv도 주입하지 않는다.\n\n### [SA] 토글 표시색\n\nnative subagent(SA) 모드가 활성화된 carrier 행은 단일 시그니처색 Rose/Magenta(fg `[216,100,168]`, bg `[30,14,26]`)로 표시된다. Rose/Magenta는 두 색이 아니라 하나의 자홍색 이름이며, provider 색이 아닌 SA 모드 식별용 중립 단일색이다. `native=true`(injection 전체 skip)는 색상 축과 무관한 별개 개념이다.\n\n### Role TOML 구조\n\nrole TOML에는 최소한 다음 필드를 둔다. `effort` 필드는 Codex가 거부하므로 사용하지 않는다.\n\n```toml\nname = \"vanguard\"\ndescription = \"Vanguard carrier role for Fleet native Codex subagents.\"\nmodel = \"o4-mini\"\nmodel_reasoning_effort = \"medium\"\ndeveloper_instructions = \"\"\"\nFleet carrier persona and operating guidance for Vanguard.\n\"\"\"\n```\n\n- `model`: Codex에 전달할 모델 identifier.\n- `model_reasoning_effort`: 추론 강도 (`low` / `medium` / `high`). 이전의 `effort` 필드는 폐기한다.\n\n### Codex Spawn argv 주입\n\n```bash\ncodex \\\n  -c 'agents.vanguard.description=\"Vanguard carrier role for Fleet native Codex subagents.\"' \\\n  -c 'agents.vanguard.config_file=\"/abs/path/to/.fleet/codex-agents/vanguard.toml\"'\n```\n\nargv는 `fleet-cli` Codex dedicated CLI builder가 store-owned config path를 받아 주입만 담당한다.\n\n## Claude Code 경로\n\nClaude Code는 기존 `--agents <JSON>` 인라인 주입 경로를 그대로 유지한다. Codex와 달리 TOML 파일 생성 단계 없이 spawn 인자에 JSON을 직접 전달한다.\n\n## 왜 inline developer_instructions argv가 아닌가\n\nCodex의 `[agents.<role>]` registry entry descriptor는 `description`, `config_file`, `nickname_candidates`만 지원하는 것이 확인된 경로이다. `developer_instructions`는 role TOML 파일 내부에서 파싱되므로, `-c agents.<role>.developer_instructions=...` dotted override는 Fleet의 정식 등록 경로로 사용하지 않는다.\n\n## 패키지별 적용 경계\n\n- `packages/fleet-carriers`: carrier persona와 subagent metadata를 provider-neutral role model로 변환하고, `~/.fleet/codex-agents/<roleKey>.toml` write/remove/path I/O를 담당한다.\n- `runtime/fleet-cli`: Codex dedicated CLI builder에서 store-owned config path를 받아 `-c agents.<roleKey>.*` argv 주입만 담당한다.\n- `packages/fleet-admiral`: Claude 전용 문구를 provider-neutral native subagent 안내로 조정하고, native subagent carrier는 일반 Fleet roster와 중복 노출되지 않도록 유지한다.\n- `packages/unified-agent` 및 ACP: dedicated CLI wave와 분리한다. 이 scope에서 다루지 않으며 별도 설계 wave로 판단한다.\n\n## 안전 체크리스트\n\n- `config_file`은 절대 경로를 사용한다.\n- role key는 bare carrier id를 그대로 사용하고, built-in 예약어(`default`/`explorer`/`worker`/`awaiter`)와 충돌 시 에러로 차단한다.\n- role TOML의 `name` 필드가 registry key와 일치하는지 검증한다.\n- role 파일은 `~/.fleet/codex-agents/`에 두고 `~/.codex`, project `.codex`, workspace `.fleet`를 오염시키지 않는다.\n- TOML write는 atomic write + fsync + rename 패턴을 사용한다.\n- `effort` 필드를 role TOML에 포함하지 않는다 (Codex 거부).\n- `native=true` carrier에는 TOML 파일 생성 및 argv 주입을 생략한다.\n- Fleet `carrier_jobs` 결과 수집과 Codex 내부 native subagent 결과 수집은 같은 채널이 아니므로 혼동하지 않는다.\n\n## 검증 근거\n\n- 로컬 Codex CLI: `codex-cli 0.135.0`, `multi_agent stable true`, `multi_agent_v2
