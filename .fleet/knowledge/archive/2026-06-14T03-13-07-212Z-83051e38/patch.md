{"id":"synthesis-fleet-console-main-dashboard-research","title":"Fleet Console 메인 대시보드 개선 조사","tags":["synthesis","fleet-console","fleet-cli","mission-control","dashboard","ux","product"],"created":"2026-06-14T03:13:07.212Z","updated":"2026-06-14T03:13:07.212Z","version":1,"body":"# Fleet Console 메인 대시보드 개선 조사\n\n## 목적\n\nFleet Console 메인 화면은 Fleet의 웹 Bridge 첫 화면이다. 현재 화면은 연결 상태와 간단한 집계만 보여주기 때문에, Fleet가 지향하는 다중 LLM 지휘·관측·지식 운영 제품의 첫 인상과 실제 운영 판단을 충분히 전달하지 못한다.\n\n이 문서는 웹 Fleet Console의 사이트맵, CLI Mission Control의 동선과 제공 기능, 그리고 두 표면을 연결해 메인 화면에서 제공해야 할 정보와 기능 제안을 정리한다.\n\n## 현재 진단\n\n웹 메인 화면은 live connection, workspace count, live job count, Operations 진입 동선 중심이다. 그러나 Fleet 제품에서 중요한 질문은 “몇 개가 존재하는가”보다 “지금 어느 Theater가 작전 가능하고, 어떤 함장과 지식 표면이 준비됐으며, 다음 명령은 무엇인가”다.\n\n따라서 메인은 단순 landing이나 welcome 페이지가 아니라, 선택된 Theater의 작전 준비도와 다음 행동을 보여주는 지휘 상황판이어야 한다.\n\n## Fleet Console 사이트맵\n\n### Global Shell\n\n- 상단 글로벌 내비게이션: Fleet Console 브랜드, Theater 선택, Operations, Codex, Local Shell.\n- Theater 선택: 프로젝트 루트를 선택하는 전역 컨텍스트. Theater는 Fleet 작업 공간의 상위 개념이며, Wiki가 있는 Theater만 Codex 표면을 사용할 수 있다.\n- Local Shell: 현재 웹 콘솔에서 열 수 있는 로컬 셸 오버레이.\n\n### `/console`\n\n- 역할: Welcome 또는 메인 대시보드.\n- 현재 제공 정보: workspace count, live job count, connection 상태, Operations 진입 버튼.\n- 제품상 부족한 점: active/deregistered 상태 구분, Theater 준비도, Carrier 준비도, Wiki 상태, 인증/서버 상태, 최근 활동이 메인에서 보이지 않는다.\n\n### `/console/operations`\n\n- 역할: 활성 Theater의 Admiral station 및 terminal session 관측 표면.\n- 현재 관찰된 상태: 활성 Theater에 Admiral station이 없으면 빈 상태와 launch 안내가 보인다.\n- 기대 역할: 실행 중인 Fleet 세션, carrier job history, stream overlay, terminal session을 Theater 단위로 보여주는 운영 관측실.\n\n### `/console/codex`\n\n- 역할: 활성 Theater의 Fleet Wiki/Codex 지식 표면.\n- Wiki가 있는 Theater: Codex reading surface, command palette, Drydock, Index, Log, Conflicts를 제공한다.\n- Wiki가 없는 Theater: Codex unavailable 상태를 보여주며, 해당 Theater에 Fleet Wiki data가 없음을 설명한다.\n\n### Codex 하위 표면\n\n- Reading surface: Fleet Wiki 문서 읽기와 탐색.\n- Command palette: Wiki entry 검색과 이동.\n- Drydock: pending queue와 archived patch 상태 확인.\n- Index: 전체 entry 목록과 metadata 확인.\n- Log: 최근 drydock, patch, index rebuild 이벤트 확인.\n- Conflicts: 미해결 충돌 확인.\n\n## Fleet CLI Mission Control 동선맵\n\nCLI Mission Control은 Fleet CLI의 출항 전 조작판이다. 웹 메인 화면은 이 표면의 제품 의미를 흡수하되, 웹에서는 운영 상태와 deep link 중심으로 재구성하는 것이 맞다.\n\n### Root: Mission Control\n\n- `LAUNCH`\n  - Agent CLI 선택: Claude, Claude Kimi, Codex.\n  - Enter: 선택된 Agent CLI launch.\n  - 오른쪽 이동: 다음 launch에만 적용되는 session-only model override 설정.\n\n- `OPTION`\n  - Mode: Fleet Action. 현재 제품의 단일 작전 모드 신호다.\n  - System prompt: Append 또는 Replace 전환.\n  - Metaphor: Enabled 또는 Off 전환.\n  - 옵션 토글은 즉시 UI에 반영되고 전역 옵션 저장 대상으로 이어진다.\n\n- `SYSTEM`\n  - Carrier Roster.\n  - System Menu.\n  - Exit.\n\n### Carrier Roster\n\n- Mission Control에서 Carrier 설정을 확인·조정하는 표면.\n- 각 Carrier의 역할, model, effort, Task Force 구성, subagent 여부를 확인하는 데 쓰인다.\n- Fleet 제품 관점에서는 “어떤 함장이 어떤 모델과 태세로 대기 중인가”를 보여주는 핵심 readiness surface다.\n\n### System Menu\n\n- Authentication\n  - provider별 인증 상태 확인.\n  - API key 등록, 교체, 삭제.\n\n- Wiki Server\n  - Fleet Wiki server 상태 확인.\n  - workspace open 또는 reopen.\n  - server stop.\n  - port 설정.\n\n- Diagnostics\n  - Fleet data directory 확인.\n  - Node, OS, shell, terminal, current working context 같은 시스템 정보 확인.\n\n- About\n  - Fleet CLI version과 channel.\n  - Carrier count.\n  - Wiki entry count.\n  - queued patch count.\n  - Docs 상태.\n  - Node runtime.\n\n## 제품 원칙\n\n1. 웹 메인은 CLI Mission Control을 그대로 복제하지 않는다.\n2. CLI는 launch/control surface이고, 웹은 operations/readiness surface다.\n3. Theater는 모든 웹 정보의 기본 축이다.\n4. Fleet의 핵심 가치는 다중 Carrier, 실행 관측, 지식 운영의 결합이다.\n5. 브라우저에는 인증 토큰, ingest token, session token, terminal ticket, admin token이 노출되면 안 된다.\n6. raw working directory path는 기본 노출보다 label 중심으로 보여주고, 필요 시 의도적 reveal/copy 패턴으로 제공하는 편이 안전하다.\n\n## 제안사항\n\n### 1. Mission Control Parity Dashboard\n\n웹 메인을 CLI Mission Control의 제품 의미를 반영한 dashboard로 재정의한다. Launch, Options, System 상태를 카드가 아니라 작전판 섹션으로 보여주고, 현재 Theater에서 바로 실행 가능한 행동만 버튼으로 둔다.\n\n### 2. Theater Command Brief\n\n선택된 Theater의 상태를 첫 화면에서 요약한다. 포함 정보는 Theater label, Wiki availability, active Admiral station count, terminal session count, registered/deregistered 상태, 최근 activity다. 단순 workspace count보다 작전 가능 여부를 알려주는 정보가 우선이다.\n\n### 3. Launch Readiness Panel\n\nClaude, Claude Kimi, Codex launch 가능 여부와 기본 선택 상태를 보여준다. 인증 누락, model override, system prompt mode, metaphor mode를 함께 표시해 사용자가 launch 전에 실패 가능성을 판단할 수 있게 한다.\n\n### 4. Carrier Readiness Matrix\n\nCarrier Roster의 핵심 정보를 웹 메인에 compact matrix로 노출한다. Carrier 이름, 역할, model, effort, Task Force tag, subagent tag, 상태를 한눈에 보여주면 Fleet의 다중 함장 제품성이 첫 화면에서 살아난다.\n\n### 5. Knowledge Readiness Panel\n\nCodex/Fleet Wiki 상태를 요약한다. Entry count, pending queue, archived patch, unresolved conflicts, latest drydock result, recent log를 보여주고, 각 항목은 Codex 하위 표면으로 이동하는 deep link를 제공한다.\n\n### 6. Operations Readiness Board\n\nOperations에 들어가기 전 active session, live jobs, recent completed jobs, failed jobs, empty-state action을 메인에서 보여준다. “지금 작전 중인가”와 “무엇을 바로 관측할 수 있는가”가 메인의 핵심이어야 한다.\n\n### 7. System Health & Admin Strip\n\nAuthentication, Wiki Server, Diagnostics, About에서 확인 가능한 정보를 웹 메인 하단 또는 우측 rail에 요약한다. version/channel, update availability, wiki server status, port, provider auth status를 표시하되 민감 정보는 노출하지 않는다.\n\n### 8. Theater Capability Matrix\n\n여러 Theater가 등록된 경우 Theater별 capability를 비교한다. Wiki available, Codex available, active Admirals, sessions, last activity, unavailable reason을 보여주면 사용자는 어느 프로젝트로 이동해야 하는지 바로 판단할 수 있다.\n\n### 9. Unified Activity Feed\n\nFleet jobs, terminal session events, Wiki drydock/log events를 하나의 최근 활동 feed로 합친다. Fleet는 실행과 지식이 분리된 도구가 아니라 하나의 작전 흐름이므로, 메인에서 시간순 연결성이 보여야 한다.\n\n## 우선순위 제안\n\n1. Theater Command Brief와 Operations Readiness Board를 먼저 도입한다. 현재 메인의 빈약함을 가장 빠르게 해결한다.\n2. Knowledge Readiness Panel을 붙여 Codex/Fleet Wiki가 웹 콘솔의 핵심 축임을 첫 화면에 드러낸다.\n3. Launch Readiness Panel과 Carrier Readiness Matrix로 CLI Mission Control의 readiness 정보를 웹에 연결한다.\n4. System Health & Admin Strip은 민감 정보 노출 경계를 정한 뒤 추가한다.\n5. Unified Activity Feed는 event model 정리가 필요하므로 후순위로 둔다.\n\n## 결론\n\nFleet Console 메인은 welcome page가 아니라 Fleet Bridge여야 한다. 첫 화면은 “살아있는 Fleet”, “준비된 Carrier”, “사용 가능한 Wiki”, “다음 명령”을 동시에 보여줘야 한다.
