# Gateway 구현 참조

Gateway 레이어·모델 카탈로그·request policy·provider adapter를 변경할 때 해당 절을 읽는다. 일반 패키지 작업의 필수 사전 읽기 목록은 아니다.

## Layer index

| Layer | Responsibility |
|---|---|
| `src/canonical/index.ts` | Direction-neutral request/event vocabulary the wire and every adapter speak |
| `src/downstream/wire/` | Inbound protocols, one folder per wire. `anthropic-messages/` holds `protocol.ts` (the only module upstream may borrow) and `inbound.ts` (the Messages⇄canonical translator) |
| `src/downstream/harness/` | One folder per client, plus `contract.ts`. `claude-code/` carries its request vocabulary (`context.ts`), its id grammar (`discovery.ts`), and its `profile.ts`; `grok-build/` carries its own dotless id grammar and profile. The Anthropic discovery envelope both render into is the wire's (`protocol.ts`), not either client's |
| `src/transport/` | Direction-unaware transport mechanics: SSE framing, token estimate, wire log, keepalive, credential file I/O |
| `src/router/` | The HTTP serving seam behind explicit host-injected dependencies. `router.ts` routes; `request-policy.ts` carries the request-shaping contract and its step implementations; `http.ts`/`passthrough.ts` are its response primitives |
| `src/upstream/<provider>/` | One folder per provider, each gateway provider declaring its own `request-policy.ts`. `anthropic/` is the native passthrough and declares none. |
| `src/acp/` | The agy ACP session port (`session.ts`, one `agy acp` child per session) and the Messages bridge adapter `bridge/` that serves Antigravity (Gemini) models through it. Not a `src/upstream/` provider: the bridge keeps live sessions between requests |
| `src/models.ts`, `models.json` | Model catalog, context windows, and effort ladders — bare catalog vocabulary, no harness id grammar |
| `src/auth/` | Provider credentials the user supplies as API keys: the `<dataDir>/auth.json` durable store, its provider-id namespace, and the Anthropic-compatible key-validation probe |
| `src/settings/` | Which catalog models a user exposed and where that choice is stored: stored shape, catalog-checked validation, selection resolution, the opt-in `providerPriority` spend order, and the `<dataDir>/ai-gateway.json` durable store |
| src/quota/ | Provider-neutral quota vocabulary, window normalization, and the cached usage service; per-provider probes live beside each provider as src/upstream/<provider>/quota.ts |

## Routing doctrine

- `models.json` + `src/models.ts` are the single central catalog SSoT; never split them or move ownership. The catalog carries each vendor lineup's current generation only — a superseded generation leaves the catalog instead of aging in place.
- Provider behavior belongs to `src/upstream/<provider>/`. Which client the gateway is serving belongs to `src/downstream/harness/<client>/`; the protocol that client speaks belongs to `src/downstream/wire/<wire>/`.
- `src/router/` is the sanctioned serving seam and the only layer that may import both directions: it may import harness profiles and provider folders for dispatch, receives every host concern (settings reader, credentials, originator, model override, diagnostics sink, fetch) as explicit dependencies, and carries no host identity, no environment lookups, and no host lifecycle of its own.
- Which shaping a caller request receives before it reaches a provider is that provider's declaration, never the router's branch. `router.ts` routes — body, model, exposure, credential, gateway construction, dispatch, error mapping — and holds no per-provider request condition. `src/router/request-policy.ts` owns the `GatewayRequestPolicy` contract and every step's implementation; each `src/upstream/<provider>/request-policy.ts` states which steps its wire deserves and why. A provider without a policy fails to compile rather than inheriting another provider's answer, and the direction-boundaries test pins both that file's presence and its shape.
- The step implementations stay with the seam because they read Claude Code's own request vocabulary from `src/downstream/harness/claude-code/context.ts`, which no provider folder may import. So the one dependency pointing back at the seam is a provider naming the contract it implements, and it is `import type` only — the edge is erased at runtime and the seam still owns every real module. Any other upstream import of `src/router/` is a violation.
- A provider policy shapes the catalog, and a rewrite of what the client wrote is placed by who must receive it. A rewrite that has to cover the native Anthropic requests no policy sees belongs above the policies, unconditional in `router.ts` — the usage-limit directive strip is the one such step. A rewrite that must **not** reach the passthrough belongs in the policies instead, because that is the only seam native traffic never enters — the client identity/billing strip is the one such step, and it is declared by each current gateway provider rather than centralized so that a provider added later states its own answer. Measure before adding a second: Claude Code attaches its shell-first directive on the Opus coordinate alone and never on a request that names a gateway model, so a gateway target and that paragraph do not co-occur outside the `FLEET_AI_GATEWAY_MODEL` override, and a stripper written for it was measured inert and removed.
- `src/downstream/wire/` must not import `src/downstream/harness/`. The wire serves every client that speaks it; an id grammar, a context coordinate, or a retry ladder reaching in there is what makes the package single-client. A client-specific value arrives as an injected function on the call options (`findModel`, `retryableStatus`) and its implementation stays in that client's folder. Absent means the neutral answer — no status lift — never Claude Code's.
- A client fact is a `GatewayHarnessProfile` field (`src/downstream/harness/contract.ts`), never a branch in `router.ts`: probe paths, credential shape, model id grammar, discovery payload, unconditional request sanitation, and retry-status mapping. `deps.harness` absent is Claude Code, so a host that names no client keeps today's behaviour. Adding a client means adding a profile, not editing the router.
- Which harness serves a request is a **declared path segment**, never a judgment about the caller. `deps.harnesses` keys are selector segments, matched as the segment immediately preceding the wire endpoint suffix (`/ai-gateway/grok/v1/messages` → `grok`); an unknown or absent segment falls to `deps.harness`. Header sniffing — user-agent, credential shape, request fields — is forbidden here: it puts the client condition the profile seam removed back into `router.ts`, and it silently mis-serves any client that resembles another. The client writes its own base URL, so the segment costs it nothing.
- Provider-specific dispatch glue — code that builds an inbound translator or calls the router's passthrough for one provider — belongs to `src/router/`, not to that provider's folder. The provider owns its header and body policy; the router owns which path a turn takes.
- Same wire protocol is not a reason to share provider request/response/tool/header/capability semantics — duplicate provider semantics deliberately.
- Only canonical protocol vocabulary (`src/canonical/`), direction-unaware transport mechanics (`src/transport/`), and exactly one inbound-wire module — `src/downstream/wire/anthropic-messages/protocol.ts` — may be shared across providers. It is borrowed only by providers whose upstream wire IS the downstream wire, which relay a caller request without translating it; no gateway provider does so today. `src/transport/` must not import either direction, and `src/upstream/anthropic/native.ts` is Anthropic-owned provider semantics other providers must not import.
- Provider request/response/tool/header/capability exceptions cannot live in `canonical/`, `transport/`, or the root facade.
- `src/settings/` is a catalog reader, never a provider: it may consume `src/models.ts` and the Claude compatibility seam, but must not import a provider folder or carry provider request/response semantics. Hosts wire it with an explicit data root and an optional legacy directory; the package resolves no host path of its own.
- `src/auth/` owns where a user-supplied provider key is stored and how such a key is checked, and nothing else. Like `src/settings/` it is provider-neutral — it must not import a provider folder, and a provider's own coordinates (its store id, base URL, validation model) stay with that provider. It is also the one place in this package that may construct a credential store: provider folders and quota collectors still receive an `AuthService` explicitly, so no probe can reach a global credential file on its own. `auth.json`'s name and its stored provider-id strings are the user's signed-in state — renaming or automatically deleting existing entries, including entries for a removed provider, silently discards that state. Preserve them even when a provider is no longer offered. Subscription credentials that a vendor CLI owns are not this: those files stay read-only reads in `src/upstream/<provider>/credentials.ts`.
- `src/index.ts` is a compatibility facade only: it re-exports the public surface from the new locations and must not add provider branching or behavior.
- The one sanctioned downstream→upstream coupling is `AnthropicMessagesGateway`'s backwards-compatible default constructor (`src/downstream/wire/anthropic-messages/inbound.ts` → `upstream/codex/responses/adapter.ts`, the legacy `OpenAIResponsesAdapter`). It is pinned by the direction-boundaries test; any other downstream import of an upstream folder is a violation.

## Constraints

- Keep Fleet orchestration and persona semantics out of this package; it knows providers, not Fleet personas.
- Provider usage/quota probing lives beside each provider (src/upstream/<provider>/quota.ts) with shared window vocabulary and caching in src/quota/; collectors receive their credential and auth dependencies explicitly — a collector never constructs the credential store itself. Antigravity is the exception that runs the user's `agy` CLI (`agy -p "/usage"`) and does not read a vendor credential.
- Each provider Responses implementation that applies strict mode rewrites the tool schemas it puts in strict mode and strips the resulting nulls back out on the way in — only for the tools it rewrote; a tool sent with its original schema keeps its explicit nulls and any `"<null>"` text. The public OpenAI Responses surface rewrites every compatible tool by default; the Codex subscription surface preserves an explicit strict flag, defaults an omitted strict to `strict: false`, and rewrites only a compatible tool explicitly marked `strict: true`. **The rewrite and the strip are one mechanism per implementation.** Change either alone and arguments silently gain or lose meaning: a surviving null reads as a real value to the client, and an un-rewritten schema loses the omission guarantee. The rewrite, the null stripping, and the argument-delta dropping below stay local to each such implementation — never centralize or import this semantic logic across providers. A bare null therefore always means "absent" on the strict wire; a property whose own schema accepts null as a value (`dueDate: null` clears a due date) spells that null as the `"<null>"` string, which the strip turns back into null only at the paths whose schema offered that spelling. Stripping every null instead silently drops those values: the Commodore could not clear a due date or assign a mission to the Commander.
- Strict compatibility is decided by an allowlist of JSON Schema keywords, never a denylist. The costs are asymmetric — judging a tool incompatible costs that one tool its guarantee, while wrongly admitting one returns a 400 that fails the entire request, every other tool included. Widen the allowlist only against an observed acceptance.
- Each provider Responses implementation that applies strict mode drops `response.function_call_arguments.delta` deliberately. Nulls cannot be stripped from a partial JSON fragment, so forwarding fragments would let the client reassemble un-stripped arguments. Restoring argument streaming reintroduces the defect.
- Strict mode makes omission expressible; it does not stop a model from filling an argument. Models still send the default quoted in a property's own description, and stating the omission rule in that description was measured to change nothing. Do not re-attempt schema-side persuasion — treat leftover default-valued arguments as accepted, since suppressing them cannot be distinguished from a caller who meant the default.
- For the same reason, a tool whose arguments are mutually exclusive must encode that exclusivity in its schema, not its prose. Strict mode turns every optional key of one object into a required nullable key, and models fill several of them: `gpt-6-sol` repeated one browser `act` call that mixed `ref`, `selector`, and `role`/`name` 229 times. Give each alternative its own `anyOf` branch with its own required keys and `additionalProperties: false` (strict does not accept `const`), and measure the converted schema's size, since nested branches are copied per alternative.
- Claude Code resends earlier thinking blocks only while its model is unchanged. Reasoning metadata from one provider therefore reaches another provider's adapter only through a gateway-side model change — the operator override or routing — which Claude Code cannot see. Every adapter replays only reasoning of its own origin and strips the replay metadata from its wire, however the conversation arrived.
- `FLEET_GATEWAY_WIRE_LOG` names the default file target for the inbound tool catalog, the canonical and provider wire bodies, and every response event as unlimited-append JSONL. An explicit in-process override takes precedence over the environment target; only override targets with `maxBytes` rotate at that limit and retain one `.1` backup. This log is the only way to see the argument JSON a model actually produced — provider behaviour differences are not otherwise observable from either side of this package.

## agy ACP bridge

Antigravity is off unless `antigravityEnabled` is stored as true (an absent key is off, including existing installations). While it is off, Fleet does not spawn agy for `--version`, `/usage`, or `agy acp`, and Gemini models stay out of the catalog, roster, picker, and routing pool. Turning it off closes any live agy ACP sessions.

Gemini models are served by `src/acp/bridge/` (an `AiGatewayAdapter`), which maps Claude Code's Messages requests onto live `agy acp` sessions. Measured on agy 1.5.9 (2026-11-15, gemini-3.8-flash):

- **Tools** reach agy as an HTTP MCP server on a loopback listener (`mcp-server.ts`, per-session Bearer, path carries the session key). agy exposes them as `mcp_fleet_<tool>`, injects a `toolSummary` argument (stripped), and runs calls serially, so a Messages response carries one `tool_use` (a 40 ms coalescing window). When the model calls a tool the response ends with `tool_use` while the ACP prompt stays open and the MCP call is held; the next request's `tool_result` releases it. agy holds a call 180 s by default; the bridge writes `timeoutSeconds: 3600` (a 1500 s hold was measured to resume normally). A deadline or `notifications/cancelled` abandons the call: the session is dropped, never continued, and its later output is not forwarded.
- **History** has no ACP entry point, so each session remembers a hash chain of the history it produced (`history.ts`). A request whose history prefix matches continues that session; otherwise (compaction, rewind, retry, a changed tool set, an abandoned call) a new session is opened and the history is replayed as `<conversation_history>` turns in the first prompt, with the instructions in `systemPrompt.append`. The tool set and model are part of the session identity because agy fixes its tools when the session opens.
- **Built-in tools** are removed, not denied: `--agent fleet-bridge` (a custom agent with `excludeDefaultComponents: true`), the MCP server in `<gemini-dir>/config/mcp_config.json` with per-tool `eager: true` (a boolean `eager` rejects the whole server config), and `session/request_permission` answered `allow_once` only for `Run mcp_fleet_*`. Failed alternatives: `tools: []` (also removes the MCP tools), a named `tools` list (registry miss), settings deny rules (not used). agy still exposes `manage_task`, `list_resources` and `read_resource`: with no shell they have nothing to act on and `list_resources`/`read_resource` only see the bridge's MCP server (empty list, not-found). Their calls are never forwarded; any other tool call in the ACP stream fails the turn and drops the session. The session cwd is an empty directory under its gemini-dir.
- **Upstream errors** are not an ACP signal. agy 1.5.9 retries an upstream failure itself (a 429 `RESOURCE_EXHAUSTED` ran 8 attempts, about 147 s), reports each attempt as an ordinary `agent_message_chunk` (`⚠ API error (attempt N): RESOURCE_EXHAUSTED (code 429): …`), and then ends the prompt with `stopReason: "end_turn"` and no error field, so the turn looks successful. The only detector is therefore a string pattern anchored to that notice (`parseAgyUpstreamError` in `events.ts`: a chunk starting with `⚠` that has the `API error (attempt N):` prefix or a `<GRPC_STATUS> (code NNN):` shape). On a match the bridge never forwards the text: it cancels the prompt, closes the session (never reused) and answers with an Anthropic error — an HTTP status when the response has not started (the adapter waits up to 8 s for the first output), an SSE `error` frame after. Mapping: 429/`RESOURCE_EXHAUSTED` → 429 `rate_limit_error`; 503/`UNAVAILABLE` → 529 `overloaded_error`; 401/403/404/400 → their `authentication`/`permission`/`not_found`/`invalid_request` errors; 504 → 504; anything else → 5xx `api_error`. A notice split across chunks loses its code and is treated as an error with no code (below); revisit the pattern if agy changes the wording. Some failures carry no code at all (measured: `⚠ There was a network issue connecting to the server, please try again.` as the whole turn, ended `end_turn`, after which the session answered the same text again without calling the model). A turn whose entire output is one short `⚠ ` text, with no tool call and no other text, is therefore treated as an upstream error: 529 `overloaded_error` (Claude Code retries it), session dropped. A genuine answer that happens to be a single `⚠ ` line is a false positive of this rule, accepted because the alternative records the error text as the assistant's answer.
- **User text beside a tool result** (Claude Code's `# Environment update…` after a `cd`, a `<system-reminder>`, an interjected message) is steered, not replayed. Measured 2026-11-15 (agy 1.5.9, gemini-3.8-flash): sending a second `session/prompt` while the turn is blocked on a held MCP call makes agy answer the **first** request `end_turn` at once, keeps the turn going, and — once the tool result is released — shows the model the new text as a user message **after** the tool result; the turn then ends with the second request's response (one answer, one `turn-end`; the first request's response is not a turn end and the session port drops it). The bridge therefore sends the user content with `steer()` first and then releases the held call with the unmodified tool result; the route stays `continue` and `bridge.request` logs `steered: 1`. If steering cannot be sent (no running turn, closed session) it falls back to the rebuild path. Before this, 7 of 13 requests in a real session were rebuilds (about +2.5 s to first output, replays of 5.8k–14.6k characters).
