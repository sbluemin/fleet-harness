# Isolated Console setup

Build and boot the owned Console before connecting with the selected browser driver. Consult **Isolated Development Data** in `docs/fleet-development-reference.md`. If the run may start Claude (terminal or SDK/chat), complete [Claude state and trust preflight](claude-state.md) first, leaving only its folder-dialog Theater trust step for after boot; Fleet slot isolation alone does not isolate agent state.

## Before a paid or long run

During planning, before boot or agent launch, check only the prerequisites the run needs. This additional preflight applies to paid provider calls and runs that may exceed the runner's default background lifetime, not short no-provider screen checks.

- **Runtime contents (paid runs):** during planning, select the check for the artifact this run will execute: [standalone package `dist/index.js`](../../ai-gateway-loop-optimization/references/execution.md#standalone-provider-loop-runner), [headless launcher `dist/fleet.mjs`](live-agent-prompt-testing.md#headless-claude-code-through-the-built-launcher), or [Operation/serve host `dist/cli.mjs`](live-agent-prompt-testing.md#serve-bundle-freshness). The executing session must run that check in the target worktree and record its output and return code before the first paid provider call. After **each source edit**, rebuild that artifact and repeat the check before the next first paid call, counting a string this latest edit adds: an earlier edit's marker stays in a stale artifact, so it still passes. When the edit adds no such string (a pure removal), record the rebuild's exit code instead. A previous successful build or check is not evidence for the edited source. A failing check blocks paid calls until the required artifact is rebuilt and passes. Free/no-provider preparation and verification are exempt from this additional content gate, even during a long run; the existing build, isolation, and reload/restart requirements still apply.
- **Runtime lifetime (long runs):** record the expected time from the owned runtime's launch (`serve`, or the Desktop launch) through setup, scenarios, retries, capture, and cleanup, with a margin. Check the chosen runner's current timeout limits and explicitly set the timeout of the managed launch process to cover that whole window; a quick successful boot does not prove that the runtime will survive it. On Desktop, ending the launcher does not stop the app ([Stopping the owned Desktop](desktop/setup.md#stopping-the-owned-desktop)), so a runner timeout leaves the app running unmanaged rather than ending it; the same budget keeps capture and that section's stop helper inside the run. If the window cannot fit, split the run into separately booted, verified segments and keep their evidence separate. Record the selected lifetime with the launch command.
- **Authentication and model exposure (paid runs):** choose a no-provider fixture when it proves the claim; otherwise identify the authorized credential route before boot. If the claim needs the user's own login, read [When the claim needs a real login](#when-the-claim-needs-a-real-login) now and prepare its authorization and launch allowlist, rather than discovering the owned-home limitation after a turn. For a client-selected non-Claude gateway model, run the existing [slot model check](live-agent-prompt-testing.md#a-fresh-runtime-directory-exposes-no-gateway-models) against the planned slot now. A fresh slot may need the documented add-model UI after boot: plan that no-cost setup, then repeat the check before launching the Operation or sending a paid call. A failing check blocks paid execution, not the no-cost configuration needed to fix it. Reconfirm the actual launch against real-login step 5 before the first paid call. This preflight checks the launch route and model exposure, not whether the Keychain login is present or valid; leave credential access to the product and keep its existing stop-on-authentication-failure rule.

## Isolate the Console

Never restart or reuse an unknown Console daemon. Build the requested source, choose a unique runtime directory, and start `serve` through [the isolated-environment wrapper](#keep-the-real-home-out) so that no unrelated browser tab opens and no real home is inherited:

```bash
cd <worktree>
export PATH="<pnpm-bin>:$PATH"
pnpm --filter @dotobokuri/fleet-console build
E2E_DIR="<repo-root>/.fleet/e2e-<role>-<short-id>"   # see "Place the run directory" below
node <worktree>/.claude/skills/console-e2e/scripts/isolated-env.mjs --run-dir "$E2E_DIR" \
  -- node <worktree>/runtime/fleet-console/dist/cli.mjs serve
```

The wrapper gives the host and every child it starts `$E2E_DIR/home` as `HOME`, together with `FLEET_DATA_DIR` (`root`), `FLEET_CONSOLE_DATA_DIR` (`console`), `FLEET_DESKTOP_DATA_DIR` (`desktop`), and `CLAUDE_CONFIG_DIR` (`claude`) under the run directory. It passes nothing else from the calling environment, which drops `INIT_CWD`, the parent Console's slot paths, session markers, and tokens. `CLAUDE_CONFIG_DIR` matters even in a UI-only run: adding a Theater through the folder dialog records Claude trust in the host's selected Claude config, which is the user's `~/.claude.json` without it. `FLEET_CONSOLE_DATA_DIR` isolates the Console slot, including credentials, durable state, lock, and gateway selection. `FLEET_DATA_DIR` also isolates host-shared data and legacy migration sources, so setting only the Console slot is not a no-user-data-write guarantee. These variables do not isolate Claude: before an agent run, complete the preflight's additional launch checks. (`FLEET_CONSOLE_DIR` is the former name of `FLEET_CONSOLE_DATA_DIR` and still works.)

`dist/cli.mjs` is the `fleet console` entry itself, so its subcommands take no `console` prefix: `cli.mjs console stop` fails with `Unknown fleet console command: console` and leaves the lock. Run `serve` as the managed process and end it with `stop`. `start` and `restart` reuse the Console that the slot's lock names, or spawn a detached `serve` whose output is discarded, so they leave nothing for this run to manage.

**Place the run directory** at `<repo-root>/.fleet/e2e-<role>-<short-id>`, where `<repo-root>` is the main checkout (the first `git worktree list` entry), whose `.fleet/` is git-ignored, and `<role>` is a short tag for this session (an objective member's role, abbreviated) that no other session of the same work uses. It survives a session restart, which objective work needs. When the wrapper refuses it as another session's, choose another name; never stop that Console or delete its directory. Keep the whole path within about 78 bytes on macOS (about 81 on Linux): `tsx` listens on `<run-dir>/tmp/tsx-<uid>/<pid>.pipe`, and a socket path past the OS limit is truncated without an error, so concurrent `tsx` helpers collide. The wrapper refuses a longer run directory with the measured length. The length check decides: a linked worktree's `.fleet/` and the session scratchpad usually exceed the limit. The objective's evidence directory lies under `~/.fleet`, which the wrapper refuses. A throwaway Theater is not a run directory: put it outside every repository, in the session scratchpad, so that neither git nor an agent's parent `CLAUDE.md` lookup reaches the checkout. A Theater that needs git gets its own `git init`. A session restart can remove the scratchpad, so recreate and re-register the Theater after one.

### Keep the real home out

The Console Shell surface (the toolbar **Shell** button) starts the host's `$SHELL` with the host's `HOME`. A host that inherits the real home therefore writes the user's shell history and reads their startup files. The same holds for measurement commands such as `zsh -i` or a shell startup timing. Earlier runs mixed test commands into the real `~/.zsh_history` this way. Run every owned host, every pnpm or `tsx` helper (such as the onboarding seed below, because pnpm and `tsx` keep caches and state under `HOME`), and every command that starts a shell or an agent CLI through [`scripts/isolated-env.mjs`](../scripts/isolated-env.mjs), with the same `--run-dir`. The exceptions bullet below lists the helpers that run outside it.

```bash
node <worktree>/.claude/skills/console-e2e/scripts/isolated-env.mjs --run-dir "$E2E_DIR" \
  [--bin <name|abs-path>]... [--set NAME=VALUE]... [--check] -- <command> [args...]
```

- **Start checklist, before the first command of a run:** [place the run directory](#isolate-the-console); pass **Before launch** below; route every host, shell, agent CLI, pnpm, and `tsx` command through the wrapper; read the lock only with the [fixed read](#read-the-lock-without-the-token); and stay within **Real-home reads**. The **Self-check** at the end of this list closes the run.
- **Before launch:** run the same invocation with `--check`. It prints the owned directories, the `pathbin` links, `PATH`, `SHELL`, and the names (not values) of `--set` variables, and it starts nothing. The wrapper refuses a run directory, `--bin`, or `--set` path inside the real home's agent, Fleet, shell-history, or credential stores (`~/.claude`, `~/.claude.json`, `~/.fleet`, `~/.codex`, `~/.agent-browser`, `~/.config`, `~/.ssh`, Keychains, shell history and rc files, and similar) or inside an inherited Fleet or Claude directory, after resolving symlinks. It checks each `:`-separated segment of a `--set` value. It resolves every relative segment, including a bare one such as `.claude/x`, against the current directory, where the child also runs. It refuses `~`, because nothing expands it. It also refuses `--set` for the variables it manages and for credential-like names (`*TOKEN*`, `*API_KEY*`, `ANTHROPIC_*`, `CLAUDE_SECURESTORAGE_CONFIG_DIR`, `CLAUDE_CODE_CHILD_SESSION`, `SSH_AUTH_SOCK`, ...). It refuses a run directory [owned by another session](#isolate-the-console): one whose `owner` file records a different caller (a hash of the Fleet Operation id or Claude Code session id), even after that session's Console exited, or an ownerless one whose lock, read only for `port` and `pid`, names a live process. This session's own run directory passes after a restart or a forced kill, and the first caller claims an ownerless one exclusively. Fix a refusal by choosing an owned path, never by working around the check. A `--set` path to a probe or preload kept in the objective's evidence directory is refused: copy it into the run directory and pass the copy.
- **`PATH`:** a fresh `$E2E_DIR/pathbin/call-*` directory for each call, then the system directories. It links only the running `node` and that call's `--bin` entries (a name resolved on the caller's `PATH`, or an absolute path), and it is removed when the command exits. A later call on the same run directory therefore never adds a CLI to a host that is already running, such as `--bin claude` reaching a fake-only Console. A Node version manager's directory often also holds globally installed agent CLIs (`codex`, `gemini`, `opencode`, ...), so it is never put on `PATH` whole. Add `--bin pnpm` when the command needs pnpm, and name an agent CLI explicitly, for example `--set CLAUDE_BIN=<worktree>/.claude/skills/console-e2e/scripts/fake-claude.mjs --set FAKE_CLAUDE_DIR="$E2E_DIR/fake-claude"`.
- **Exceptions, stated only here:** outside the wrapper, by design, run the browser driver (agent-browser, Fleet Browser), [`close-owned-session.mjs`](../scripts/close-owned-session.mjs), [`cdp-input.mjs`](../scripts/cdp-input.mjs), and the Desktop helpers ([`desktop-preflight.mjs`](../scripts/desktop-preflight.mjs), [`stop-owned-desktop.mjs`](../scripts/stop-owned-desktop.mjs), [`main-inspector.mjs`](../scripts/main-inspector.mjs)). These locate sessions under the real home or only talk to an owned endpoint. So do plain-Node HTTP helpers that start no shell, agent CLI, pnpm, or `tsx`, such as [`fake-claude-mcp.mjs`](../scripts/fake-claude-mcp.mjs) and console-handoff's `seed-console.mjs`, and the workspace install and build (`pnpm install`, `pnpm --filter … build`), which write only the checkout and pnpm's own store and start nothing under the run. Inside it run the host's own launcher commands, including `cli.mjs stop` with the same `--run-dir`, so that it never sees an inherited Fleet root. A Desktop launch keeps its own owned-`HOME` allowlist in [Desktop setup](desktop/setup.md), because macOS `open` relaunches the bundle with the caller's environment. On Windows, where the wrapper does not run, apply the same owned-path allowlist by hand and report it as such. The one credential-like value the wrapper forwards is the fixed local placeholder `--set ANTHROPIC_API_KEY=sk-ant-fleet-local`, which is not a credential (see [the headless launcher](live-agent-prompt-testing.md)). Any other real store — the user's Claude home, an environment credential, the real Fleet root — needs the user's explicit authorization for that store. Such a run starts outside the wrapper, is disclosed before launch per the [Claude state preflight](claude-state.md), and is reported as non-isolated for that store. [When the claim needs a real login](#when-the-claim-needs-a-real-login) is that route for the user's own Claude or Cursor login.
- **After the run:** the wrapper reports which entries appeared in the owned home. After a shell ran in the Shell surface, `.zsh_history` (or the shell's equivalent) there is the positive evidence that history went to the owned home. For a stronger check, type a unique no-op marker such as `: fleet-e2e-<unique-id>` in that shell, close it, and confirm that `grep -c` finds it in `$E2E_DIR/home/.zsh_history`.
- **Real-home reads:** the only reads of real-home files allowed are the scoped digests in the [Claude state baseline](claude-state.md#record-the-baseline-before-any-child-starts) and `grep -c <unique marker>` against the user's shell history file, which prints a count only and should find 0. A denied read leaves that check unverified, not clean. Never print or copy real-home file contents. The whole of `~/.claude` is real home, including auto-memory under `~/.claude/projects/<project>/memory/`, other sessions' transcripts and `projects/` records, settings, and plugin data. Apart from the baseline's scoped checks there (named-file digests and this Theater's trust entry or `projects` directory), listing, searching, or opening anything under `~/.claude` is a read outside this allowance. Memory that the agent harness itself loads into context at session start is not a read by the run.
- **Process listings:** identify processes only by the PIDs and ports recorded for this run, and print only the columns the check needs, for example `ps -p <pid> -o pid,ppid,stat,etime` or `lsof -nP -iTCP:<owned port> -sTCP:LISTEN`. Print a command line only where a lane needs it to prove what an owned PID runs, and then only for that PID. An agent CLI's command line carries the Console-issued MCP bearer tokens in its inline `--mcp-config`, so never print or log an agent child's command line, even an owned one: use `ps -p <pid> -o comm=` or a `grep -c` count, and make a process tracer or preload record only the executable basename and subcommand. A whole-table `ps` or `pgrep` listing such as `ps aux`, `ps -ef`, `pgrep -fl`, or `pgrep -af` prints other sessions' command lines, which can carry paths, prompts, and tokens. An `lsof` that is limited neither to a recorded PID (`-p`) nor to an owned port (`-iTCP:<port>`) lists other sessions' processes and files. The Desktop helpers read the process table internally and print no command line or environment. Besides owned PIDs and the listeners on the ports they check, `desktop-preflight.mjs` prints the PIDs and executable paths of the caller's ancestor chain and responsible process. In `--occlusion` mode it also prints the app names and PIDs of other windows that cover the owned window. A process's environment is never printed (see [Claude state](claude-state.md)).
- **Self-check before reporting:** confirm that each command that started a host, a shell, an agent CLI, or a pnpm or `tsx` helper for the run went through the wrapper. Confirm that no real-home read went beyond the allowance above, including anything under `~/.claude`. Confirm that no process listing went beyond the run's own PIDs, that no output, including an error message, printed a lock body, token, or ticket, that recorded WebSocket and network URLs dropped their query string, and that no command ran `security`, `login`, or token-refresh helpers. Report a command that ran outside the wrapper as a possible leak with its effect, rather than declaring the home untouched. Report a read or a listing beyond these bounds the same way: name the command and what it exposed.

The wrapper is an environment boundary for macOS and Linux, not an OS sandbox. It does not isolate the macOS Keychain (see [credential limits](claude-state.md#select-a-child-route-not-just-an-environment-variable)), launchd session keys that `open` adds to a Desktop launch, or network access, and a child can still write to an absolute path it is given. The self-check above applies to the exceptions as well.

A fresh slot has no provider credentials. Do not copy real credentials, trigger login/token refresh, or silently reuse a user's root to make a test pass. Prefer a no-provider fixture when it proves the claim. A real-provider scenario needs an explicitly authorized credential path and quota use, with any non-isolated stores disclosed before launch.

Run the server as a background/managed process with the lifetime selected in [long-run preflight](#before-a-paid-or-long-run) when applicable, wait for `$E2E_DIR/console/console.lock`, read its port with the fixed read below, and confirm the route returns `200`. Seed a real Theater through the Console folder UI or authorized API only when the scenario needs it; do not copy the user's durable state. An API-registered Theater stays untrusted for Claude, so a terminal Operation that must receive a Console prompt needs the folder-UI route in [the trust preflight](claude-state.md#prepare-folder-trust-through-the-normal-gate).

Client changes require build plus reload. Host changes require build plus isolated server restart. Compare the asset name in `dist/client/index.html` with the served `/console/` HTML before blaming stale behavior.

#### Read the lock without the token

Print only `port` and `pid` with this fixed read. It catches a parse failure itself, because a JSON error message quotes part of the file:

```bash
node -e 'try { const l = JSON.parse(require("fs").readFileSync(process.argv[1], "utf8")); if (!l.port || !l.pid) throw 0; console.log(JSON.stringify({ port: l.port, pid: l.pid })); } catch { console.error("console.lock not readable yet"); process.exit(1); }' "$E2E_DIR/console/console.lock"
```

Never `cat`, `jq`, or `grep` the lock, and never put the token in a shell variable, a URL, or a command line. A step that needs the token reads it inside the one Node process that sends the request and passes it only as a header, as [`issue-access-link.mjs`](../scripts/issue-access-link.mjs) does.

#### Restart after a forced kill

A Console that exits without its shutdown handler (`SIGKILL`, a capped kill, a crash) leaves `$E2E_DIR/console/console.lock` holding its dead PID. The next `serve` on that run directory then exits 1 within a second with `EEXIST: file already exists, open '<run-dir>/console/console.lock'`. Handle only the lock of this run's own `$E2E_DIR`, and never delete it by hand:

1. Take `pid` from the [fixed read](#read-the-lock-without-the-token).
2. Probe it with `node -e 'try { process.kill(Number(process.argv[1]), 0); console.log("alive"); } catch (e) { console.log(e.code); }' <pid>`, and continue only on `ESRCH`. For any other result, do not run `stop`: it signals whatever process now holds that PID, so a reused PID would receive `SIGTERM` and then `SIGKILL`. Prove the PID is this run's `cli.mjs serve` from the recorded worktree by comparing its command line without printing it, for example `ps -p <pid> -o command= | grep -cF '<worktree>/runtime/fleet-console/dist/cli.mjs serve'`, since a reused PID is not owned and the [process-listing bounds](#keep-the-real-home-out) allow printing only an owned PID's command line. If it is, a live owned Console holds the lock, so stop and restart it normally. If it is not, stop and report it.
3. Run `cli.mjs stop` through the [wrapper](#keep-the-real-home-out) with the same `--run-dir`. With a dead PID, `stop` only removes the lock.
4. Start `serve` again as in [Isolate the Console](#isolate-the-console), with the same wrapper flags as the first boot (such as `--set CLAUDE_BIN=…`), then take the new port with the fixed read.

#### When the claim needs a real login

Use this route only when the claim needs a model turn that only the user's own login can authenticate, and no fixture or authorized slot credential proves it. The Claude CLI and the AI Gateway's Cursor upstream (`upstream/cursor/credentials.ts`) read that login from the macOS Keychain or a credential file under the real home, so an owned `HOME` cannot see it. Step 2 replaces only the wrapper's launch of `serve` and its `--check`; every other rule in [Keep the real home out](#keep-the-real-home-out) still applies.

1. **Authorize before launch.** Get the user's authorization for this run's use of the real Claude home and Keychain logins, its paid calls, and the cleanup in step 6. Disclose before launch that the run is not isolated from those stores, per the [Claude state preflight](claude-state.md), and record its [baseline](claude-state.md#record-the-baseline-before-any-child-starts). Register a [throwaway Theater](#isolate-the-console) so that the records the run leaves are identifiable.
2. **Launch outside the wrapper with a hand-built allowlist.** First claim the run directory through the wrapper with a no-op, `isolated-env.mjs --run-dir "$E2E_DIR" -- true`, so that its [ownership check](#isolate-the-console) refuses another session's directory and records this one as owned; stop on a refusal. Then start `serve` under `env -i` with only the real `HOME`, `USER` and `LOGNAME` (a Keychain lookup fails without them), a `PATH` built as the **`PATH`** bullet above describes, `CLAUDE_BIN`, and the three Fleet paths in owned slots: `FLEET_DATA_DIR=$E2E_DIR/root`, `FLEET_CONSOLE_DATA_DIR=$E2E_DIR/console`, `FLEET_DESKTOP_DATA_DIR=$E2E_DIR/desktop`. The Fleet paths are mandatory: the real Fleet root holds the user's Console slot and the legacy sources a fresh slot migrates. Leave `CLAUDE_CONFIG_DIR` unset, because relocating it changes the Keychain service identity ([credential limits](claude-state.md#select-a-child-route-not-just-an-environment-variable)). Never add `CLAUDE_SECURESTORAGE_CONFIG_DIR`, a token, or the caller's session variables. Run `cli.mjs stop` with the same environment, and do not open the Shell surface, which would write the real shell history.
3. **Leave the Keychain to the product.** Only the Console and the agent CLI read it. Never run `security`, a login or logout, `/login`, or a token-refresh helper, and never open a credential file. When a launch reports `Not logged in` or the provider rejects the login, stop and report an environment block instead of logging in.
4. **Keep tokens out of every output.** The lock-read, process-listing, and environment rules above apply unchanged. Record an authentication or provider failure as its status code and a classification, never its raw message or response body.
5. **Spend as few paid calls as the claim needs.** Before the first one, confirm without spending that it can succeed. The Console it goes to must be the step 2 launch: a `serve` started through the wrapper has an owned `HOME` and cannot see the login, so its turn stops at `Not logged in`. Judge that from the launch command you ran, never by querying the Keychain or printing a process environment. If it fails, stop with no paid call and report an environment block. Use short prompts, and report how many turns ran on each model.
6. **Clean up the run's session records.** This route writes the run's Claude session records under the real `~/.claude/projects/`; that write is expected and authorized in step 1, not a leak under the [preflight's boundary check](claude-state.md#prove-the-boundary-and-finish). After `cli.mjs stop`, open only the directory for the throwaway Theater's path, confirm that it holds only the session ids this run recorded, and delete that one directory. When it holds anything else, delete nothing and report it. Leave everything else under `~/.claude` in place and report any other change. The Theater's trust entry stays in the real `~/.claude.json`: never edit it ([folder trust](claude-state.md#prepare-folder-trust-through-the-normal-gate)), and report it as remaining.
7. **Report the run as non-isolated** for the real Claude home and the Keychain, with the authorization, the paid-call count, the cleanup result, and the remaining trust entry. In the self-check above, name the launch as the authorized run outside the wrapper, with its effect on the real home.

### Record what is being reproduced

Before reproducing a user-reported defect, record the user's installed Fleet version or reported surface, the target SHA, and the served asset name. A local `canary` can lag or lead the user's build with a different UI; when they differ, reproduce on a detached [baseline](../../git-worktree/references/baseline.md) at the user's revision rather than assuming the newest checkout shows the same behavior. While measuring, do not let another build write the same `dist/` the owned server serves: use a separate checkout or output, and report a rebuild that landed mid-measurement as a contaminated run.

### First-load onboarding state

A fresh slot and a new origin show commissioning, What's New, entry hints, and feature tours, and they can race the scenario's first input. Prepare that state **before the first navigation** instead of dismissing layers mid-scenario. Once the lock exists, run [`scripts/seed-onboarding.mts`](../scripts/seed-onboarding.mts) with the Console package's `tsx`:

```bash
node <worktree>/.claude/skills/console-e2e/scripts/isolated-env.mjs --run-dir "$E2E_DIR" --bin pnpm \
  -- pnpm --dir <worktree>/runtime/fleet-console exec tsx \
  <worktree>/.claude/skills/console-e2e/scripts/seed-onboarding.mts \
  --console-dir "$E2E_DIR/console" --init-script "$E2E_DIR/whats-new.js"
```

- It derives every key from the current source and merges them into `seenFeatureTours` through the origin-gated `PUT /api/v1/settings/global`, then reads them back and fails when one is missing. The sources are the core contributions, each built-in plugin's `onboarding` read from its client entry as the plugin registry reads it, the seen-store key rules, and the keys stored outside any contribution (commissioning and the effort-confirm tip). `--dry-run` only lists the keys. Commissioning also opens only while no Theater is registered.
- What's New is a per-origin `localStorage` watermark, so the script writes it as a page script for `--init-script` of the session that opens the page. Every isolated-server restart picks a new port, which is a new origin: rerun the script and reopen the session. The [Fleet Browser fallback](fleet-browser.md) has no init script; there, dismiss What's New through its real control and record that the watermark could not be preset.
- When the claim concerns onboarding, a tour, or a hint, do not seed or dismiss the layer under test: pass `--keep <key>` (or a prefix ending in `.`, such as `objectives.`) for it, which also clears that key on a reused slot, omit `--init-script` when What's New is under test, and install diagnostics before the first navigation so its appearance and race stay observable.
- Confirm the first screenshot shows no unseeded onboarding layer before acting.

The same run can lay down two common fixtures, each opt-in and read back before the script reports success:

- `--deputy <tori|bori|dori>` (repeatable) turns that scuttlebutt deputy on and marks its introduction as shown through `PUT /api/v1/settings/plugins/scuttlebutt`, so the deputy appears without the intro bubble. The script takes the deputy ids from the plugin's settings store. Deputy conversations are not seeded: the plugin keeps no conversation history, so a scenario that needs one needs a live gateway turn.
- `--wiki <entry-id> --theater <theater-id> --theater-dir <folder>` stages one entry with the product's `wiki_ingest` tool and approves it in the knowledge root that Codex resolves for that Theater. Entry writes otherwise go only through the approval queue. The script then reads the entry back through the Theater's `/console/codex/w/<theater-id>/api/entry/<entry-id>` route. Register the Theater first from a [throwaway Theater folder](#isolate-the-console), and pass that folder. The script refuses before any write when the folder does not hash to the Theater id, because the Wiki resolver would otherwise migrate and label another folder's `.fleet/knowledge`. An id that starts with a Wiki template prefix (such as `prd-`) must satisfy that template, so use a neutral id such as `e2e-fixture`. A rerun on the same slot keeps the existing entry.

### No-cost fake Claude

When the claim needs a live agent process, MCP tools, or chat protocol traffic but not model output, point `CLAUDE_BIN` at [`scripts/fake-claude.mjs`](../scripts/fake-claude.mjs) instead of the real CLI. It answers `--version`, speaks the SDK stream-json control protocol in chat (`initialize`, `set_model`, `get_context_usage`, one canned turn per user message), and otherwise stays alive as an interactive terminal that echoes input. Nothing reaches a provider, so no quota is spent and no credential is needed.

- Boot through the [Claude state preflight](claude-state.md) environment anyway: add `--set CLAUDE_BIN=<worktree>/.claude/skills/console-e2e/scripts/fake-claude.mjs --set FAKE_CLAUDE_DIR=<owned-run>/fake-claude` to the [wrapper](#keep-the-real-home-out), which keeps `node` on its `PATH`. On Windows, point `CLAUDE_BIN` at the sibling `fake-claude.cmd` instead: Console launches only `.cmd`/`.bat` shims through `cmd.exe`, so a `.mjs` path does not start. A fake binary does not make the rest of the agent route inert.
- `FAKE_CLAUDE_DIR/log.jsonl` records each launch (mode, cwd, `--session-id`/`--resume`, MCP server names), control request, turn and exit without secrets. Use it to prove which Operation launched, resumed or exited. The script header lists the control files for context size, a failing `set_model`, and a held-open turn.
- To act as that launch on Console MCP (an Objectives Commander or member, `fleet-console-use`, and so on), run [`scripts/fake-claude-mcp.mjs`](../scripts/fake-claude-mcp.mjs) `--dir <FAKE_CLAUDE_DIR> --server <name> --tool <tool> --args '<json>'`; `--list` shows the saved launches. The Console-issued bearer tokens stay in owner-only files under `FAKE_CLAUDE_DIR/mcp/`; never print or copy them. A `fleet-console-use` or `fleet-computer-use` tool called from an Operation without that use allowed waits up to four minutes on the panel's use-request card (`USE_REQUEST_HOLD_MS` in `features/console-use/host/use-requests.ts`). Unless the card is under test, allow the use first through the Operation's control in the owned page; the alternative, `POST /api/v1/experiments/sessions/<operation>/console-use` (or `computer-use`) with `{"enabled":true}` from the owned page origin, stands in for the tester's own toggle; use it, or answer a use-request card, only on the isolated Console this run owns. A call that hangs is that hold, not a dead Console.
- **After an owned Console restart,** the saved launches cannot reconnect, not even on the same port through `FLEET_CONSOLE_RESUME_PORT`: Console issues each launch's MCP bearer token in host memory, so a restart invalidates every token under `FAKE_CLAUDE_DIR/mcp/`. A fake launch survives the restart only with a captured session identity: post the capture hook described below before stopping, or Console does not persist the Operation and an objective it commands is removed at boot. Resume the restored Operation so that the fake launches again with `--resume`: `POST /api/v1/agent/sessions/<operation>/resume` with body `{}` and `Origin: http://127.0.0.1:<port>`, an origin-gated route that needs no token (an objective's Commander Operation id is the objective id). Then take the new pid from `--list` and pass it as `--pid`. Without `--pid` the script uses the newest launch that received that server.
- The fake fires no Claude hooks. Console pins a `--session-id` at launch, which keeps the Operation's identity, but a coordinate whose source is still `launch` resumes as a fresh session. To exercise a real `--resume`, post the capture hook a real CLI would send: `POST /api/v1/agent/sessions/<operation>/capture` with the lock token as Bearer, read and sent inside one Node process per [the lock read](#read-the-lock-without-the-token), and `{"provider":"claude","input":"{\"session_id\":\"<pinned id>\",\"source\":\"startup\"}"}`. Turn, attention, and background states have their own lock-token hook routes. Recheck the resume and capture contracts in `features/execution/host/agent/routes.ts` when they change.
- Objective Commence and other Console prompts into a fake terminal pass only after the Theater was added through the folder dialog ([trust preflight](claude-state.md#prepare-folder-trust-through-the-normal-gate), step 4); otherwise they return 409 `claude_trust_required` before the fake sees input.
- Label results as fixture evidence. A fake proves launch, lifecycle, MCP and protocol paths, not real CLI behavior, authentication, trust prompts, or model quality.

### Computer Use fixture (macOS)

Computer Use counts as installed only on macOS, when Codex resolves and `$CODEX_HOME/computer-use/Codex Computer Use.app/Contents/SharedSupport/SkyComputerUseClient.app/Contents/MacOS/SkyComputerUseClient` is executable (`findComputerUseInstallation` in `features/computer-use/runtime/codex-broker.ts`); otherwise turning on `experiments.computerUse` returns 409 `computer_use_install_required`, and a tool call throws the same. Call only `computer_status`: native capture and input stay unverified and remain bound by the focus rule.

### No-cost fake Commodore

The Commodore SDK does not honor `CLAUDE_BIN` and may use default Keychain authentication even with an isolated home. For no-cost autonomy transition checks, use the test-only [`fake-commodore.mjs`](../scripts/fake-commodore.mjs) loader on Node 22.15+. It replaces **only the existing `ctx.host.agent` port during objectives registration**, without changing product source or build files or running the real SDK, CLI, or provider. Other plugins and Operations are not faked; do not launch them.

```bash
cd <absolute-worktree>
pnpm --filter @dotobokuri/fleet-console build
E2E_DIR="<owned-run>"
node <worktree>/.claude/skills/console-e2e/scripts/isolated-env.mjs --run-dir "$E2E_DIR" \
  --set NODE_ENV=test --set FAKE_COMMODORE_DIR="$E2E_DIR/fake-commodore" --check \
  -- node --import <worktree>/.claude/skills/console-e2e/scripts/fake-commodore.mjs \
  <worktree>/runtime/fleet-console/dist/cli.mjs serve
```

Remove only `--check` and run the same command as a managed background process. **Before enabling autonomy**, verify that `$E2E_DIR/fake-commodore/installed.json` has `fake: true`, `plugin: "objectives"`, and a `pid` matching this Console's lock, and that `log.jsonl` contains `installed`. If any evidence is missing, stop without enabling autonomy: the loader has not been confirmed. The loader requires `NODE_ENV=test` and the wrapper's owned directory layout. No SDK child starts, so this route does not establish real authentication, CLI trust, or model quality.

In a registered throwaway Theater, enable the experiment and autonomy, then confirm `created`, `send`, and a zero-cost successful result in the transcript. Create and remove control files under `$E2E_DIR/fake-commodore/` with plain Node:

- `hold-turn`: holds the next fake turn until cancellation. Send a message, confirm `run.phase=turn` and `send.held=true`, queue another message, then turn autonomy off. Confirm `cancel`, `dispose`, and `undelivered` for both message seqs. Re-enabling must not redeliver them.
- `complete-on-cancel`: with `hold-turn`, finishes the turn with `ok` despite the stop race. That turn's message must not be marked `undelivered`.
- `hold-experiments`: create after disabling the experiment has removed the runner while stored autonomy remains true. Re-enabling records `experiments-held` and delays only subscriber notification. A message during that gap must return `409 commodore_inactive` without entering the transcript. Remove the file, confirm `experiments-released` and runner status, then confirm the same request returns 200. This is a deterministic fixture of the real host's save→async reconciliation→notification boundary, not a timing measurement of a natural race.
- `calls/<name>.json` with `{"tool":"<tool>","args":{...}}`: the fake session runs that Commodore or board tool through the `tools.custom` entry the objectives plugin passed to `createSession` and writes the result to `calls/<name>.json.out`. This proves board effects under a Commodore actor, not that a model would choose the call. The call runs outside a turn, without the host's schema check or abort signal, so it does not prove turn gating; keep one Commodore runner, and call only board tools or offline git reads, since git and gh tools run in the real Theater root and gh reaches the network.

Before cleanup, remove the control files and disable autonomy. Stop only the owned Console through the same wrapper and run directory using `cli.mjs stop`. Preserve fake logs and HTTP/transcript results as fixture evidence.

**Time-dependent state has no clock hook in a running Console.** `now` is injectable only through the Objectives store and supervisor constructor options that contract tests use. The 30-minute stall counts from the objective's `boardUpdatedAt` (epoch ms, falling back to `createdAt`); `stalledObjectives` in `runtime/fleet-plugins/objectives/server/board-state.ts` owns the other conditions, which include a commenced objective with an open mission and every observed session dormant or idle. The roster fixture above is neither commenced nor given a mission, so it never stalls. Use an objective that is commenced with an open mission and whose sessions restart dormant, such as a fake Commander that [survives a restart](#no-cost-fake-claude), stop its owned runtime, set `boardUpdatedAt` to more than 30 minutes ago, and restart. The stall shows in the Objectives inbox view and the board's cluster note, not in the `/plugins/objectives/state` response. The next board write clears it. Do not shift the clock with a `Date.now` preload or `libfaketime`: timers keep the monotonic clock, and the offset also moves stored timestamps and reaches child processes.
